## 1. 지금 구조가 못 하는 것 (구체적 결함)

### 1.1 씬을 그대로 굽는 진입점이 없다

베이크 대상은 `AtlasApplyDebug` 컴포넌트의 자식이거나, 인스펙터 배열에 손으로 끌어다 놓은 것뿐이다.
실 씬(수백~수천 오브젝트)을 굽는 정상 워크플로가 존재하지 않는다.

### 1.2 Static 플래그를 보지 않는다

`ContributeGI` 여부와 무관하게 자식 `MeshFilter` 를 전부 수집한다.
유니티 Progressive Lightmapper와 **입력 집합이 달라서 A/B 품질 비교가 성립하지 않는다.**
움직이는 오브젝트가 라이트맵에 구워지는 사고도 막지 못한다.

### 1.3 R/W 미설정 메시가 조용히 '반쪽' 처리된다 ← 실제 버그성 갭

- `LightmapAllocator.Allocate` 는 `ResolveTargets()` 가 준 **전체 filters** 로 ST를 할당한다 (`AtlasApplyDebug.cs:419-428`).
- 그런데 `BuildGiScene` 은 `if (mesh == null || !mesh.isReadable) continue;` 로 **차폐 씬에서 빼버린다** (`:1289`).
- 결과: 그 오브젝트는 **아틀라스 슬롯은 차지하는데 차폐 씬에는 없다** → 자기 그림자도, 남에게 드리우는 그림자도 없다.
  **경고 한 줄 없이** 일어난다.

### 1.4 LODGroup을 모른다

LOD0/1/2 가 전부 receiver로 들어가면 겹친 표면이 서로를 가려 얼룩이 생기고 아틀라스를 3배 쓴다.

### 1.5 파라미터화 실패가 할당 **이후에** 드러난다

`ParameterizationPipeline.Run` 예외는 베이크 루프의 try/catch가 잡고 `continue` 한다 (`:534`).
이미 할당된 ST 슬롯은 빈칸으로 남는다 — 아틀라스 이용률만 떨어지고 원인은 로그에만 남는다.

## 2. 설계 결정 (Why 포함)

### ① C0는 새 파이프라인이 아니라 '입력 공급기'다

출력은 `ResolveTargets`/`ResolveOccluderUnion` 이 이미 쓰는 것과 **같은 형태**(receiver 집합 + occluder 집합)이고,
베이크 경로 코드는 한 줄도 바꾸지 않는다.

**Why**: A1~A4 · C1 · C2 · G0~G6 · SH · α · SSAA 가 **전부 이 입력 계약 위에서 수치 검증**됐다.
계약을 바꾸면 "α 이전/이후 자릿수까지 동일" 같은 회귀 기준이 통째로 무효가 된다.
최소 침습이 곧 회귀 안전망 유지다.

### ② 수집 순서는 결정적이어야 한다

씬 계층 순회 순서를 고정한다(정렬로 흔드는 대신 순회 순서 그대로).

**Why**: 인스턴스 인덱스 `i` 가 ST 할당과 per-lumel 시드 `seed + li*2654435761u` 에 **직접 들어간다.**
순서가 흔들리면 같은 씬을 두 번 구워도 결과가 달라지고, 백엔드 교차검증(CPU≡Burst≡GPU)과
회귀 비교가 전부 무의미해진다. → **C0-V1 이 이것만 본다.**

### ③ 정책은 Runtime, 유니티 에디터 API 조회는 Editor 어댑터

- `SceneCollectPolicy` (Runtime) — 순수 함수. 입력 = 후보 배열 + 이미 조회된 플래그 비트. 출력 = 3분류 + 사유.
- `SceneCollector` (Editor) — 씬 순회 · `StaticEditorFlags` · `LODGroup` · `ModelImporter` 조회 후 정책 호출.

**Why**: Runtime asmdef는 플랫폼 제한이 없고 Tests asmdef도 `UnityEditor` 참조가 없다.
정책을 Runtime의 순수 함수로 두면 **헤드리스 테스트가 가능**하고 `#if UNITY_EDITOR` 산발을 피한다.
(`NormalTransformTests` 가 헤드리스로 도는 것과 같은 이유.)

### ④ 3분류 — Receiver / OccluderOnly / Excluded

v14.11 `occluders` 계약을 그대로 쓴다.

| 분류 | 조건 |
|---|---|
| **Receiver** | ContributeGI ∧ MeshFilter+MeshRenderer ∧ readable ∧ 월드면적>0 ∧ LOD0 ∧ 프리플라이트 통과 |
| **OccluderOnly** | readable ∧ (사용자 지정 ∨ `receiveGI=LightProbes` ∨ receiver 자격 미달이지만 지오메트리는 유효) |
| **Excluded** | 메시 null ∨ !readable ∨ 면적 0 ∨ LOD1+ ∨ 프리플라이트 실패 — **사유와 함께 리포트** |

**Why 3분류**: 대량 프롭·식생을 receiver로 넣으면 아틀라스가 폭발한다.
그림자만 필요한 것은 occluder로 강등하는 게 **α 트랙(잎 컷아웃 차폐)과 정확히 짝을 이룬다** —
잎은 굽지 않고 그림자만 드리우면 되는 대표 사례다.

### ⑤ R/W 미설정은 양쪽에서 **일관되게** 제외하고 리포트한다

**Why**: §1.3 의 반쪽 처리는 "이 오브젝트만 그림자가 없다"는, 원인 찾기 가장 어려운 증상으로 나타난다.
차폐 씬에서 빠질 거면 아틀라스 슬롯도 주지 말아야 한다.
에디터에서는 `ModelImporter.isReadable = true` 일괄 수정 버튼을 제공한다(C0-5, 선택).

### ⑥ MeshCleaner를 새로 만들지 않는다 — 추출해서 쓰고, **UV 경로에만** 적용한다 ← 가장 중요

`WeldedHalfEdge` 생성자가 이미 용접 + 퇴화 삼각형 제거를 한다. C0는 이걸 **독립 static 함수로 추출만** 하고
(로직 무변경), 정제 결과는 **파라미터화 입력에만** 쓴다. 차폐 씬 지오메트리는 원본 `mesh.triangles` 를 유지한다.

**Why**: 차폐 씬의 `Tri[]` 는 `mesh.triangles` 순서를 그대로 쓰고,
α의 `TriUV`/`TriSubmesh` 가 **그 순서에 1:1로 대응**한다.
`AlphaMaskBuilder.BuildScene` 은 `tris.Length/3 != nTri` 면 그 메시의 알파를 꺼버린다(`AlphaMaskBuilder.cs:317`).
수집 단계에서 정제한 메시를 차폐 씬에 넣으면 삼각형 수가 달라져 **α가 조용히 꺼진다.**

→ C0가 하는 일은 정제 '실행'이 아니라 **정제 가능성 프리플라이트 + 진단**
(비매니폴드/퇴화/중복 정점 개수 리포트). 이중 정제는 하지 않는다.

### ⑦ 프리플라이트를 할당 **앞으로** 옮긴다 (단, 값싼 검사만)

`ParameterizationPipeline.Run` 은 비싸므로 전수 실행하지 않는다.
값싼 사전조건만 본다 — 정점/삼각형 0, 월드면적 0, UV0 없음, 서브메시 255 초과, 비매니폴드 경고.

**Why**: 할당 후에 실패하면 아틀라스에 빈 슬롯이 남는다(§1.5).
무거운 검사는 여전히 베이크 루프의 try/catch 가 최종 안전망이다 — C0는 **싼 값에 걸러낼 수 있는 것만** 앞당긴다.

### ⑧ 결과는 에셋이 아니라 값이고, 사람이 고칠 수 있어야 한다

`SceneCollection` 은 직렬화 대상이 아닌 결과 구조체다.
`AtlasApplyDebug` 에는 **"Collect Scene" 메뉴**로 붙어서 `targets`/`occluders` 인스펙터 배열을 채우기만 한다.

**Why**: "어떤 프롭을 occluder로 내릴지"는 자동 판정이 100% 맞을 수 없는 영역이다.
수집 결과를 눈으로 보고 손으로 고칠 수 있는 지점을 반드시 남긴다.
(α의 `alphaForceCutout`/`alphaForceCutoutNames` 탈출구와 같은 철학.)

## 7. 상위 로드맵과의 관계

- 파이프라인 **단계 1의 나머지 절반**. "알파 마스크"는 α 트랙에서 완결됐고, C0는 그것을 **호출**만 한다(재구현 금지).
- **B1(Track B, 범용 프로브 격자)** 이 같은 수집 결과를 **프로브 배치 입력**으로 재사용한다 —
  프로브를 어디에 깔지는 "어떤 지오메트리가 씬에 있는가"에서 나오므로, C0가 먼저 있어야 B1이 손으로 안 채워도 된다.
- `AtlasApplyDebug.occluders`(v14.11)는 C0의 **출력 소비처**다. C0가 그 배열을 자동으로 채운다.

→ **권장 순서: ✅α → C0 → B1(Track B)**
