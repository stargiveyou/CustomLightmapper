# 커스텀 라이트매퍼 — 희소 브릭 프로브 설계 (Track B · B4, 선택)

> 상태: **설계만 — 미착수**(2026-10-29). 착수 기준은 §12.
> 상위 문서: `커스텀_라이트매퍼_TrackB_식생프로브_설계.md` §4.8(결정 ⑥ 적응형 프로브의 두 번째 선택지) · 개발 원칙 기획서 §9.5(자체 파이프라인 — Unity APV·라이트 프로브를 쓰지 않음).
> 선행: B2 지형 추종 2.5D(v15.22). 위치 배열 베이크(`ProbeGrid.BakeBurstAt`/`BakeGpuAt`)·유효성(`BurstProbeValidity.BackfaceRatio(positions)`)이 이미 임의 위치를 받는다.
> 번호: Track B 의 B2 두 번째 선택지지만, B3(제외) 다음 번호인 **B4** 로 부른다.

## 0. 한 줄 요약

프로브를 3D 공간에 두되 **지오메트리 근처만 촘촘히, 빈 공간은 듬성듬성** 둔다. 프로브 4×4×4 묶음(브릭)을 간격 1·3·9배 레벨로 깔고, 셰이더는 작은 **인디렉션 텍스처**로 "이 위치는 어느 브릭"인지 찾은 뒤 **브릭 아틀라스**에서 보간한다. 2.5D 로 표현 못 하는 다층 공간(다리 위/아래·건물 층·동굴·절벽 밑)을 다루기 위한 것이다.

---

## 1. 목적 · 범위

### 1.1 2.5D 가 못 푸는 경우
- B2 지형 추종은 **열(XZ)마다 지면 하나**를 가정 → 한 열 위의 바닥이 여러 개면 맨 위 바닥 기준으로만 층을 쌓는다.
- 예: 지면 메시에 다리가 들어가면 층이 다리 상판에서 시작 → 다리 밑 식생이 상판 위의 밝은 빛을 읽는다. 지면 메시를 지형만으로 한정하면 반대로 다리 상판 위가 비어 있다.
- 균일 3D 격자로 덮으면 하늘까지 전부 프로브: 256×64×256m 를 1m 간격 = 257×65×257 ≈ 429만 프로브 ≈ 240MB(RGBAHalf, 프로브당 56B) — 기본 `maxProbeCount`(≈210만)도 넘는다.

### 1.2 목표
- 3D 다층 공간을 프로브로 표현한다(같은 XZ 의 위·아래가 서로 다른 프로브).
- 지오메트리·식생이 없는 공간은 거친 레벨로만 덮어 메모리를 균일 대비 크게 줄인다.
- 기존 계약 유지: SH9(L2) · 반사 규약 ρ/π·E · 직사광 실시간 · CPU 샘플 ≡ 셰이더 샘플(미러) · 결정적 베이크.

### 1.3 범위 밖
- **벽 너머 누수**: 배치 문제가 아니라 보간 가중 문제 — 가시성 가중(DDGI 식 깊이 모멘트)은 별개 주제.
- 런타임 스트리밍·동적 재베이크.
- Unity APV 재사용(기획서 §9.5 — 자체 구현).

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 기본 간격 s₀ | 가장 촘촘한 프로브 간격(예 1m) |
| 레벨 l | 프로브 간격 s_l = s₀·3^l (l = 0 이 가장 촘촘). 기본 L = 3 레벨(1·3·9m) |
| 브릭 | 레벨 l 의 프로브 4×4×4 묶음 = 셀 3×3×3 을 덮는 정육면체(한 변 3·s_l) |
| 인디렉션 칸 | 레벨 0 브릭 크기(한 변 3·s₀)의 공간 칸. 인디렉션 텍스처 텍셀 1개 = 칸 1개 |
| 브릭 아틀라스 | 모든 브릭의 프로브를 4×4×4 블록으로 빽빽이 담은 Texture3D×7 |
| 점유(occupancy) | 칸 근처에 지오메트리/식생이 있어 세분해야 하는가 |

레벨 배율이 3 인 이유: 브릭 하나가 셀 3칸을 덮으므로, 간격을 3배로 키운 상위 레벨 브릭 1개가 하위 레벨 브릭 3×3×3 = 27개와 **경계가 정확히 겹친다**(트리 구조가 정렬됨).

## 3. 구조

### 3.1 브릭 · 레벨
- 브릭 (l, b) 의 원점 = 볼륨 원점 + b·(3·s_l), b = 정수 3D 브릭 좌표. 프로브 (i,j,k) ∈ [0,3]³ 위치 = 원점 + (i,j,k)·s_l.
- 볼륨 전체는 최상위 레벨(L−1)로 **항상** 덮는다(빈 공간도 — 기본안, §10 결정 2). 점유된 곳만 아래 레벨로 세분(8분할이 아니라 27분할).
- 한 위치는 **가장 촘촘한 레벨의 브릭 하나**가 담당한다(상위 레벨 브릭은 하위가 덮지 않은 부분만 담당).

### 3.2 인디렉션
- 레벨 0 칸 격자(dims = ⌈볼륨 / (3·s₀)⌉) 3D 텍스처. 텍셀 = (담당 브릭의 아틀라스 블록 좌표, 레벨).
  - 상위 레벨 브릭은 자기가 덮는 3^l × 3^l × 3^l 칸 모두에 같은 값을 쓴다 → 셰이더는 칸 하나만 읽으면 된다.
  - 형식 후보: `Texture3D` R32_UInt(블록 x 10bit · y 10bit · z 8bit · 레벨 4bit 패킹) — `GraphicsFormat` API·플랫폼 지원 확인 필요(§10 결정 4). 대안: RGBA16_UInt 또는 StructuredBuffer.
- 크기 예: 256×64×256m, s₀ = 1m → 칸 86×22×86 ≈ 16만 텍셀 × 4B ≈ 0.65MB.

### 3.3 브릭 아틀라스
- Texture3D×7(RGBAHalf — 기존 계수 텍스처와 같은 레이아웃: 텍스처 t = 프로브 SHPacked float4 t). 브릭 블록을 (bx, by, bz) 3D 블록 격자에 채운다 → 아틀라스 크기 = 블록 수 × 4. 축 한도 2048 → 축당 블록 512 — 블록 격자 모양은 총 브릭 수로 정한다.
- **경계 중복**: 이웃 브릭이 경계 면의 프로브를 각자 갖는다 → 브릭 안에서 HW trilinear 가 아틀라스의 다른 블록으로 새지 않는다. 대가로 같은 영역에 균일 대비 64/27 ≈ **2.4배** 텍셀(§8). 대안(중복 없이 셰이더 수동 8탭)은 §10 결정 1.

### 3.4 레벨 경계(T-정션)
- 레벨 0 브릭 옆에 레벨 1 브릭이 있으면, 공유 면에서 촘촘한 쪽의 일부 프로브는 거친 쪽 격자에 없는 위치다 → 양쪽 보간이 다르면 면에서 값이 튄다(이음매).
- 처리(§5.6): 촘촘한 브릭의 **경계 면 프로브를 거친 쪽 보간값으로 덮어쓴다** → 면 위 보간이 양쪽에서 같아져 연속. 면에 딱 붙은 디테일만 잃는다.

## 4. 세분 판정 (점유)

- 최상위 → 아래 순서로, 레벨 l 칸마다 "칸을 여유 d_l 만큼 키운 AABB 안에 무엇이 있나" → 있으면 27분할.
- **세분 원천**(§10 결정 5):
  1. 정적 지오메트리 근접 — 삼각형 AABB ∩ 칸 AABB(`TwoLevelBVH` 에 AABB 겹침 질의를 새로 추가: TLAS 인스턴스 AABB → BLAS 노드 → 삼각형 AABB, CPU·결정적). 짧은 레이 여러 발 방식은 얇은 지오메트리를 놓치므로 비권장.
  2. **템플릿 인스턴스(식생) 바운드** — 식생 조명이 목적이라 식생이 있는 곳은 지오메트리가 드물어도 세분.
  3. (선택) 사용자 세분 박스.
- 여유 d_l = 0.5·(3·s_l) + normalBias 정도 — 샘플이 경계 브릭으로 넘어가지 않게.
- **예산**: 브릭 수가 `maxProbeCount` 를 넘으면 레벨 0 세분을 원천 우선순위(식생 > 지오메트리)로 자르고 로그에 보고.
- 결정성: 칸 순회 순서 고정(레벨, z, y, x) · 부동소수 판정은 정수 칸 좌표 기준.
- 지형 카펫은 거의 전부 점유 → 레벨 0 브릭이 땅을 다 덮는다(이 경우 2.5D 가 더 쌈 — §8). 혼합안(지형 = 2.5D, 구조물 = 브릭)은 §10 결정 6.

## 5. 베이크 파이프라인

1. **세분** → 브릭 목록 (l, b), 정렬 (l, b.z, b.y, b.x).
2. **고유 프로브 표**: 모든 브릭 프로브의 위치를 레벨 0 정수 격자 좌표 (s_l = 3^l·s₀ 라 모든 레벨 프로브가 이 격자 위)로 키 → 중복 제거(같은 레벨의 공유 면 + 레벨 사이 일치 위치). 브릭 → 고유 프로브 인덱스 표(브릭당 64).
   - **중복 제거가 필수인 이유**: 다바운스 시드가 프로브 인덱스(seed + idx·2654435761u)라 같은 위치를 두 번 구우면 값이 달라 이웃 브릭 경계에서 튄다.
3. **SH 베이크**: 고유 위치 배열 → `ProbeGrid.BakeBurstAt` / `BakeGpuAt`(B2 에서 생김, 무변경).
4. **유효성**: `BurstProbeValidity.BackfaceRatio(고유 위치)` → `Classify`(무변경).
5. **Dilation**: 고유 프로브 그래프 — 이웃 = 같은 브릭 안 6-이웃(브릭 사이는 고유 인덱스로 자동 연결). 링 단위·스냅샷 방식은 기존 `Dilate` 와 같게.
6. **레벨 경계 이음매**(§3.4): 촘촘한 브릭의 면 중 이웃이 더 거친 레벨인 면 → 그 면의 고유 프로브를 거친 브릭 trilinear 로 덮어쓴다(거친 쪽 값은 이미 dilation 완료).
7. **아틀라스 채우기**: 브릭마다 64 프로브의 SH 를 블록 텍셀로 복사 → Texture3D×7. 인디렉션 텍스처 작성.

## 7. 셰이더 계약 (`HuskyProbeVolume.hlsl` 세 번째 경로)

- `_HuskyPV_Params.w = 2` → 브릭 경로(0 = 균일, 1 = 지형 추종 — 기존 경로 무변경).
- 샘플 순서:
  1. 칸 c = floor((p − origin) / (3·s₀)), 볼륨 밖이면 경계 칸으로 클램프(기존 클램프·페이드 규칙과 같게).
  2. `_HuskyPV_Indirection.Load(c)` → (블록 좌표 B, 레벨 l).
  3. 브릭 원점 = origin + floor(c / 3^l)·3^l·(3·s₀), 브릭 안 좌표 u = clamp((p − 브릭 원점) / s_l, 0, 3).
  4. uvw = (B·4 + u + 0.5) / 아틀라스 dims → `SampleLevel` ×7 → `UnpackSH9` → `EvaluateSH9`.
- 추가 비용: 의존 텍스처 읽기 1회(인디렉션) — 식생 셰이더 정점 단계(`_HUSKY_PV_PIVOT`)에서도 동작.
- CPU 미러(`ProbeVolumeShaderBinding`)는 같은 식 — GPU ≡ CPU 테스트의 기준.

## 8. 메모리 모델

- 아틀라스 텍셀 = Σ_l (브릭 수_l × 64), 프로브 바이트 = 텍셀 × 56B(RGBAHalf ×7). 고유 프로브(CPU 배열)는 중복 제거로 더 적다.
- 인디렉션 = 레벨 0 칸 수 × 4B.
- 균일 대비 같은 영역 오버헤드 = 64/27 ≈ 2.4배 → **점유율이 약 40% 를 넘는 레벨 0 영역에선 균일보다 비싸다**. 브릭 이득은 3D 로 띄엄띄엄한 공간에서 난다.

**예시(가정 명시 — 어림)**: 도시 블록 256×64×256m, s₀ = 1m, 3 레벨.

| 배치 | 가정 | 프로브(텍셀) | 메모리 | 다층 표현 |
|---|---|---|---|---|
| 균일 1m | — | 257×65×257 ≈ 429만 | ≈ 240MB | ✅ |
| 2.5D 지형 추종 | 지면 위 8m, 1m | 257×9×257 ≈ 59만 | ≈ 33MB | ❌(한 층) |
| 희소 브릭 | 레벨 0 칸 8% 점유 · 레벨 1 칸 30% · 레벨 2 전역 | 레벨 0 ≈ 1.3만 브릭 + 레벨 1 ≈ 0.2만 + 레벨 2 300 ≈ 1.5만 브릭 × 64 ≈ 98만 | ≈ 55MB(+ 인디렉션 0.65MB) | ✅ |

넓은 지형 위 식생만이면 2.5D 가 가장 싸고, 다층 구조가 있으면 브릭이 균일보다 크게 싸다(이 예에서 −77%).

## 9. 단계 · 검증

| 단계 | 내용 | 검증(테스트) |
|---|---|---|
| **S1** 배치 코어(헤드리스) | `ProbeBrickLayout`: 레벨·브릭 목록(점유 함수 주입)·고유 프로브 표·인디렉션 값·CPU 샘플 | 전부 레벨 0 ≈ 같은 간격 균일 격자(샘플 ≤ 1e-5 — 브릭 원점 기준 부동소수 경로가 달라 비트 동일은 아님) · 선형장 재현 · 중복 제거 수 해석해 · 인디렉션 ↔ 브릭 왕복 · 결정성 |
| **S2** 세분 판정 | `TwoLevelBVH` AABB 겹침 질의 · 템플릿 바운드 원천 · 예산 | 다리 씬(지면 + 상판): 상판 위·아래 모두 레벨 0 · 빈 하늘 = 최상위만 · 질의 ≡ 브루트포스 삼각형 AABB 대조 |
| **S3** 베이크 | 고유 위치 베이크 · 유효성 · 그래프 dilation · 레벨 경계 이음매 | 에셋 SH ≡ 코어 직접(고유 위치, 비트 동일) · 공유 프로브 1회만 베이크 · 레벨 경계 면 양쪽 샘플 연속(\|Δ\| ≤ ε) · dilation 채움 |
| **S4** 에셋·셰이더 | 아틀라스·인디렉션 텍스처 · `HuskyProbeVolume.hlsl` 경로 · 바인딩 · CPU 미러 | GPU ≡ CPU(내부·레벨 경계·볼륨 밖·페이드) · glslang · 균일/지형 추종 경로 무변경(기존 테스트) |
| **S5** 베이커 통합 | `ProbeVolumeBaker.layout = SparseBricks` · 설정(레벨 수·기본 간격·세분 원천·예산) · 로그·기즈모(레벨별 색) · 매뉴얼 | 다리 씬 실베이크: 상판 아래 프로브 E(up) < 위 · 절감률 리포트 · Uniform/TerrainLayers 회귀 비트 동일 |

모든 단계는 기존 원칙대로 Tests 어셈블리 + RunAll 배선, 헤드리스로 가능한 부분은 .NET 에서 실제 실행.
