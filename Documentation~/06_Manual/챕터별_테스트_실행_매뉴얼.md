> 기준: `main` v15.19(2026-10-27, 머지 `ab60df7`) · 패키지 `com.huskylibs.customlightmapper` · Unity 6000.x + URP

## 0. 이 문서 읽는 법

### 0.1 도구 4종류

| 종류 | 위치(어셈블리) | 쓰는 법 |
|---|---|---|
| **실행 소스(베이커)** | `Runtime/` | GameObject 에 컴포넌트 추가 → 인스펙터 설정 → **우클릭(⋮) 컨텍스트 메뉴**. 실제 결과물(라이트맵·SH·프로브 볼륨)을 만든다 |
| **디버그 하니스** | `Samples/` | GameObject 에 컴포넌트 추가 → 우클릭 메뉴. 파이프라인 중간 결과를 기즈모·텍스처로 보여 준다 |
| **테스트** | `Tests/` | `LightmapEvaluateDebugger` 우클릭 메뉴(아래 §0.2) 또는 코드 `Debug.Log(X.RunAll())`. 콘솔에 PASS/FAIL 리포트 |
| **에디터 메뉴** | `Editor/` | 상단 메뉴바 `HuskyLibs/…`·`Husky/…` 또는 컴포넌트 우클릭(`CONTEXT/…`) |

### 0.2 테스트 실행 공통 절차

1. 씬에 빈 GameObject 를 만들고 **`LightmapEvaluateDebugger`** 컴포넌트를 붙인다(테스트 메뉴 모음 — 필드는 비워 둬도 된다).
2. 인스펙터 우클릭 → **Run All Tests (C1+C2)**(전체 38종) 또는 챕터별 묶음 메뉴(§3.2).
3. 콘솔 결과 읽기:
   - 테스트 클래스마다 `=== 이름 ===` 머리줄 → 항목별 `[PASS]` / `[FAIL]` / `[SKIP]` → 끝줄 `--- n/m PASS ---`.
   - `[SKIP]` 은 실패가 아니다 — 그 항목에 필요한 환경(compute·URP 셰이더·그래픽 디바이스)이 없다는 뜻. 사유가 같은 줄에 찍힌다.
   - FAIL 을 보고할 때는 **그 `[FAIL]` 줄 + 그 클래스의 `--- n/m PASS ---` 줄**을 함께 남긴다.
4. 테스트는 임시 오브젝트·메시·에셋을 숨김(HideAndDontSave)으로 만들고 끝에 지운다 — 열린 씬을 바꾸지 않는다. 로컬 광원을 쓰는 베이커 테스트는 광원 출처를 `None` 으로 고정해 열린 씬의 라이트와 무관하다.

### 0.3 요구 조건 표기

| 표기 | 뜻 | 없으면 |
|---|---|---|
| **없음** | 씬·GPU 불필요 — 에디터에서 그대로 실행. ★ 표시는 이 저장소 밖(.NET 헤드리스)에서도 실제 실행해 확인된 것 | — |
| **Compute** | compute shader 지원 GPU + `Shaders/Resources/*.compute` 로드 | 해당 항목 `[SKIP]` |
| **URP** | URP 활성 + 패키지 셰이더(`LightmapDebug`·`InstancedSH_URP`·`InstancedVegetation_URP`) | 해당 항목 `[SKIP]` |
| **렌더** | 그래픽 디바이스로 실제 렌더(StructuredBuffer·RT 읽기) | 해당 항목 `[SKIP]` |

### 0.4 사전 체크

| 항목 | 이유 |
|---|---|
| 임포트 메시 **Read/Write Enabled** | 정점·삼각형을 CPU 에서 읽는다. 꺼진 메시는 베이크에서 빠지거나(경고) 오류(템플릿) |
| Compute 지원 GPU | GPU 백엔드·GPU 테스트. 없으면 베이커는 Burst 로 자동 폴백(로그 남김) |
| URP | 라이트맵 표시(`LightmapDebug.shader`)·SH 표시(`InstancedSH_URP`)·식생(`InstancedVegetation_URP`) |
| Burst 속도 측정 시 | `Jobs ▸ Burst ▸ Safety Checks Off`, Leak Detection Off(성능 비교 메뉴만 해당) |
| 출력 폴더 | 베이커 결과는 기본 `Assets/CustomLightmapper/BakeOutput`(자동 생성) |

샘플 씬: `Samples/Mesh_Struct_Sample_Scene.unity`.

## 2. 챕터별 사용법

### 2.1 A1 — 메시 구조 · 차트 분할

메시를 하프에지로 바꾸고(정점 용접), 이면각·노멀 편차로 차트를 자른다. 라이트맵 UV(uv2)의 출발점.

**실행 소스**

| 컴포넌트 | 우클릭 메뉴 | 사용 순서 |
|---|---|---|
| `HalfEdgeConversion` | Rebuild HalfEdge | MeshFilter 가 있는 오브젝트에 추가 → 메뉴 → 씬 뷰에서 하프에지 화살표(`bIsDrawHalfEdge`)·경계 에지(빨강, `highlightBoundaryEdge`) 확인. `halfEdgeShrink`·`halfEdgeArrowSize` 로 가독성 조절 |
| `ChartSegmentationDebugger` | Run Segmentation · Run Segmentation - Welded · Clear Result | `targetMesh`(비우면 같은 오브젝트의 MeshFilter) → 메뉴 → 차트별 색·시임(검정)·외곽 루프(cyan)/구멍 루프(magenta). `settings.SeamAngleDeg`(40°)·`MaxChartAngleDeg`(60°) 를 바꿔 재실행. 결과 `chartCount`·`faceCount`. Welded = 용접본 기준 |

**에디터 메뉴** — `HuskyLibs/CustomLightmapper/Scene Collect (C0)/Diagnose Selected Meshes (Weld · Degenerate)`: 선택(자식 포함) 메시의 용접으로 줄어드는 정점 수·퇴화 삼각형 수를 보고만 한다(메시 무변경).

**테스트** — 전용 테스트 없음. 분할 결과를 쓰는 평탄화가 `ChartFlattenTests`(§2.2)로 검증된다.

### 2.2 A2 / A3 — 평탄화(Planar → LSCM → MVC) · UV 조립

차트를 2D 로 편다: 평면 투영 → 겹침·늘어남(L2 stretch)이 크면 LSCM 등각 → 그래도 겹치면 MVC 전단사. 이어 차트들을 uv2 메시로 조립(시임 정점 분리 + SeamTable).

**실행 소스**

| 컴포넌트 · 메뉴 | 사용 순서 · 보는 것 |
|---|---|
| `ParameterizationTestDebugger` — Run Parameterization Check · Clear Result | `targetMesh` + `settings`(분할) + `flatten`(평탄화) → 메뉴 → 차트 루프·foldover 차트(빨강). 결과 `chartCount`·`foldoverCharts`·`degenerateTriangles`. 콘솔에 차트별 방법(Planar/LSCM/MVC)·stretch 집계 |
| `UVAssemblerTestDebugger` — Run UV Assemble · Clear Result | 조립 정합성(정점 분리 수 = 기대값, 삼각형 보존, 시임 그룹). `applyToMeshFilter` 면 조립 메시를 입혀 보고, `copyUV2ToUV0` 로 uv2 를 텍스처 좌표로 확인. 이 단계는 패킹 전이라 차트가 UV 에서 겹치는 게 정상 |
| 메뉴 `Husky/Tools/UV Layout Viewer` | 차트 UV 2D 캔버스 창 — foldover(빨강)·겹침, A4 패킹 토글 |

**튜닝**: 곡면이 늘어나 보이면 `flatten.PlanarStretchThreshold` 를 낮춰 더 많은 차트가 LSCM 비교를 타게 하거나 `segmentation.MaxChartAngleDeg` 를 낮춰 차트를 잘게 자른다. 같은 `flatten` 필드가 `AtlasApplyDebug` 에도 있다.

**테스트**

| 테스트 | 메뉴 | 요구 | 확인하는 것 |
|---|---|---|---|
| `ChartFlattenTests` | Run Chart Flatten Tests (A3 LSCM_MVC) | 없음 ★ | 희소 솔버(CG·BiCGSTAB·GS) · L2 stretch · 평면 회귀(Planar ≡ 구 투영 비트 동일) · LSCM(평면 ≈1·원통 120°·구면) · 270° 말림 겹침 0 · MVC(구멍 평판·원통) · 결정성 — 17/17 |

### 2.4 C0 — 씬 수집 · 분류

씬의 MeshFilter 를 **Receiver**(라이트맵을 굽는다) / **OccluderOnly**(차폐만) / **Excluded**(양쪽 제외) 로 나누고 사유를 리포트한다. 기준: 사용자 표식 → 지오메트리 사고(메시 없음·Read/Write 꺼짐·렌더러 꺼짐·삼각형 아님·면적 0) → LOD1+ → Static `Contribute GI` 꺼짐 → `receiveGI = LightProbes`.

**실행 소스**

| 메뉴 | 동작 |
|---|---|
| `AtlasApplyDebug` 우클릭 **Collect Scene (C0)** / **Collect Scene - All Loaded Scenes (C0)** | 활성 씬(또는 로드된 씬 전부) 수집 → `targets` = Receiver, `occluders` = OccluderOnly 로 교체. Receiver 0건이면 적용 안 함. Undo 가능 |
| `ProbeVolumeBaker` 우클릭 **Collect Scene (C0)** / **… All Loaded Scenes (C0)** | 같은 분류의 Receiver ∪ OccluderOnly → `collectedStatics`, `staticSource = Collected`(§2.14). 템플릿과 겹치는 물체 수를 로그 |
| `HuskyLibs/CustomLightmapper/Scene Collect (C0)/Collect Scene → Selected AtlasApplyDebug` | 선택한 오브젝트의 AtlasApplyDebug 에 수집 |
| `…/Report Only (Dry Run)` | 적용 없이 리포트만 |
| `…/Verify Determinism (C0-V1)` | 같은 씬 2회 수집 → 순서·분류·MeshFilter 목록 완전 일치면 PASS |
| `…/Diagnose Selected Meshes (Weld · Degenerate)` | §2.1 |
| `…/Options/Non-GI Static As Occluder` · `LOD1+ As Occluder` · `Strict (Exclude No-UV0 · >255 Submeshes)` | 분류 옵션 토글(체크 표시, EditorPrefs 저장 — 모든 C0 메뉴 공통) |
| 컴포넌트 `SceneCollectOverride`(`mode` = OccluderOnly / Exclude, `includeChildren`) | 자동 판정을 고정하는 표식. 나무 프리팹 루트에 하나 붙이면 자식 전부에 적용(가장 가까운 조상 표식이 이김). 재수집해도 유지된다 |

**리포트 읽기**: 머리줄 `receiver N · occluder M · excluded K` → 사유별 건수(많은 순) → 경고(UV0 없음 = 알파 컷아웃 비활성, 서브메시 255 초과) → Excluded 상세 + 조치 문구(예: NotReadable → "임포터 Read/Write Enabled 를 켜세요").

**주의**: 프리팹 편집 모드에서는 수집하지 않는다(경고). 다른 씬의 오브젝트 참조는 씬 저장 시 사라진다(교차 씬 경고) — 같은 세션에서 굽거나 씬별로 수집.

**테스트**

| 테스트 | 메뉴 | 요구 | 확인하는 것 |
|---|---|---|---|
| `SceneCollectPolicyTests` | Run Scene Collect Tests (C0) | 없음 ★ | T1 순서 보존 ~ T14 SceneMembers — 결정성·배타성·사유 우선순위(13규칙 전수)·LOD·옵션·경고 범위·리포트 형식·Pick — 21/21 |
| `ProbeVolumeC0Tests` | Run Scene Collect Tests (C0) · Run Probe Volume Tests | 없음 | 프로브 볼륨 정적 입력: Roots 구 거동 비트 동일 · Collected ≡ Roots · 템플릿 중복 제외 · 빈 입력(E 의 경고 1줄은 정상) |

### 2.5 C1 — 가속구조 BVH

단일 레벨 BVH(Median/SAH) + 2단 TLAS/BLAS(메시 공유 인스턴싱). 모든 레이 질의의 바탕.

**실행 소스**

| 컴포넌트 · 메뉴 | 사용 순서 |
|---|---|
| `BVHGizmoDebugger` — Build BVH · Create Ray Handles · Clear | `targets`(비우면 자식 MeshFilter) → Build BVH → 노드 AABB 와이어박스(`minDepth`/`maxDepth` 층 필터, `leafOnly`, 깊이별 색). `quality`(기본 SAH) ↔ Median 비교(SahCost 라벨). Create Ray Handles → `rayOrigin`/`rayTarget` 핸들 생성(`drawRay` on) — 핸들을 움직이면 순회가 실시간으로: 방문 노드 강조·컬링 노드 회색(`drawCulledNodes`)·히트 표시, `visited/culled/triTests` 통계. 오브젝트를 옮기면 다시 Build |

### 2.7 로컬 광원 — Point · Spot · Area(Rect/Disc)

씬의 Point/Spot/Area 라이트를 텍스처 라이트맵(L1: 1차 직사 + 바운스)과 SH·프로브(L2: 바운스 + 프로브가 직접 받는 빛)에 굽는다. 감쇠·스포트 각은 URP 실시간과 같은 식, 면광원은 면 샘플링으로 반그림자. Directional 은 제외(태양은 각 베이커의 태양 설정).

**설정 위치**

| 베이커 | 필드 |
|---|---|
| `AtlasApplyDebug` | `localLightSource`(기본 **Scene** / Listed / None) · `localLights`(Listed 용) · `localLightsFollowBakeType` · `areaLightSamples`(16) · `softLightSamples`(8) |
| `InstanceSceneBaker` · `ProbeVolumeBaker` | `localLights`(`LocalLightSettings`: `source`(기본 Scene) · `lights` · `followBakeType` · `areaSamples` · `softSamples`) |

- **Scene** = 로드된 씬의 켜진 로컬 라이트 전부(강도 0·꺼진 라이트 제외, 객체 ID 순 — 결정적). **None** = 구 거동(태양 + 하늘만).
- `FollowBakeType` 켜면 Unity 라이트 Mode 를 따름: Baked = 직사 + 간접 · Mixed = 간접만(직사는 실시간 라이트 몫) · Realtime = 제외.
- 라이트의 Shadow Type None → 그림자 없음, Baked Shadow Radius > 0 → 원판 샘플 반그림자(`softLightSamples` 발).
- 확인: 베이크 완료 로그 `lights=P2 S1 R1 D0(Scene)` · 프로브/인스턴스 에셋 `lightLog`.
- 씬에 로컬 라이트가 있으면 기본 Scene 이라 **이전 베이크와 결과가 달라지는 게 정상** — 비교할 땐 None.

**테스트** — 묶음 메뉴 **Run Local Light Tests (Point _ Spot _ Area)**

| 테스트 | 요구 | 확인하는 것 |
|---|---|---|
| `BakeLightTests` | 없음 ★ | Point 역제곱·창 · Spot 원뿔 · Rect/Disc ≈ 해석해(형상계수) · 그림자 · null ≡ 빈 배열(비트 동일) · 112B 레이아웃 — 7/7 |
| `LocalLightBakeTests` | URP + Compute | Unity Light 변환(Mixed → 간접만, Realtime 제외 등) · Burst ≈ CPU · 광원 0개 ≡ 구 결과 · GPU ≈ Burst · 실베이크 휘도 None < Mixed < Baked |
| `SHLightProjectionTests` | 없음 ★ | SH 직접광 투영 ≡ 격자 적분(0.06%) · 입체각 상한 2π · 넓은 면광원 SH ≈ 텍스처 조도(L2 근사) — 5/5 |
| `SHLocalLightTests` | Compute(C 항목) | SH 광원 0개 ≡ 구 결과 · Burst ≈ 레퍼런스 · GPU `CSSHDirect` ≈ Burst · 프로브/인스턴스 베이커 반영 |

### 2.9 G4~G6 — GPU 백엔드 · 배치 · 적응 샘플링 · 진행형

`PathTrace.compute` 로 같은 경로추적. 큰 씬에서 Burst 대비 6~7배. 배치 베이크·분할 디스패치·순회 스택 가드(스택 32칸 초과 트리는 Burst 폴백), 적응 샘플링, 진행형 미리보기, GPU 시임/dilation.

**사용 (`AtlasApplyDebug`)**

| 필드 · 메뉴 | 설명 |
|---|---|
| `radianceBackend = Gpu` · `pathTraceShader`(비우면 자동 로드) | compute 미지원·로드 실패·BVH 깊이 초과 → Burst 폴백(경고 로그) |
| `bakeBatchLumels`(1<<20) · `gpuDispatchChunk` | 배치 크기·디스패치 분할 — 결과는 값과 무관하게 비트 동일, 메모리·TDR 위험·진행 표시 간격만 달라짐. 0 = 인스턴스마다(구 거동) |
| `adaptiveSampling`(off) · `samplesPerPass`(8) · `adaptiveMinSamples`(16) · `adaptiveThreshold`(0.03) | 패스마다 누적, 표준오차 ≤ threshold × 휘도인 텍셀은 멈춤(`indirectSamples` = 상한). 로그 `adaptive(spp 평균 X/N, 경로 Y%)` |
| 우클릭 **Bake Progressive (Preview)** · **Cancel Progressive Bake** · `progressivePreviewEveryPasses` | 저 spp 결과를 즉시 보여 주고 패스마다 다듬음(에디터 비동기, `progressiveStatus` 표시). 끝까지 돌린 결과 = 같은 설정의 Bake & Apply. 취소하면 그 시점 결과로 확정(SSAA·저장 생략) |
| `gpuPostProcess`(off) · `postShader` | 시임 스티칭 + dilation 을 `LightmapPost.compute` 로. 결과 ≈ CPU(나눗셈 ULP 차이). 로그 `stitch(…,GPU)` · `dilate=N×(GPU)` |
| 우클릭 **RadianceGI Backend Diff (Burst vs GPU)** | Burst ↔ GPU 텍셀 대조 + 시간. `meanDiff` 1e-6 대 · `over(1/255)` 0.001% 수준이면 정상 |

**테스트** — 묶음 메뉴: **Run GPU Batch Tests (G6-3b _ G6-4)**, **Run Adaptive _ Progressive _ GPU Post Tests (G6-5 _ G6-6)**

| 테스트 | 개별 메뉴 | 요구 | 확인하는 것 |
|---|---|---|---|
| `GpuBvhCompareTests` | Run GPU BVH Compare (G4) | Compute | GPU 순회 ≡ Burst(miss 0) |
| `GpuRadianceCompareTests` | Run GPU Radiance Compare (G5) | Compute | GPU AO/Direct/Indirect ≈ Burst(평균 ~1e-9) |

### 2.10 텍스처 라이트맵 베이크(Track A) — `AtlasApplyDebug`

`Runtime/LightmapAllocator/AtlasApplyDebug.cs`. 대상 메시들을 파라미터화(A1~A3) → 할당(A4) → 텍셀 복원 → 라이팅 → SSAA → 후처리 → `Texture2DArray` 아틀라스 → 렌더러에 uv2 메시 + 라이트맵 머티리얼 적용 → 결과 저장. 필드 전체는 `02_Development_And_Reference/AtlasApplyDebug_레퍼런스.md`.

**빠른 시작 (5단계)**

1. 굽을 메시들을 빈 GameObject 의 자식으로 모으고 그 부모에 `AtlasApplyDebug` 추가(또는 우클릭 **Collect Scene (C0)** 로 `targets`/`occluders` 자동 채움 — §2.4).
2. 매핑 확인: `mode = PerInstanceColor` → 우클릭 **Bake & Apply** → 오브젝트마다 다른 단색이 겹침 없이 보이면 uv2·ST 정상. 이어 `WorldNormal`·`Checker`(`checkerSize`) 로 텍셀 복원·밀도 확인.
3. 우클릭 **From DirectionalLight Component** → 씬 태양(Directional 이 여럿이면 객체 ID 순 첫 번째)의 방향·색·세기를 `lightDirection`/`lightColor`/`lightIntensity` 로 복사.
4. `mode = RadianceGI` · `radianceBackend = Gpu`(또는 Burst) · 처음엔 `atlasResolution 256` · `indirectSamples 16` · `maxBounces 1`.
5. **Bake & Apply** → 완료 로그 한 줄: 단계별 시간 `scene(BVH+알파마스크)=` · `bake(레이트레이싱)=` · `post(denoise+stitch+dilate)=`, 후처리 `stitch(T1=…,T2=…)` · `dilate=N×(…)`, `lights=…`, (누적 시) `adaptive(spp 평균 …, 경로 …%)` → 결과 자동 저장(`saveBakeResult`). 되돌리기는 **Restore Originals**.

**모드(`mode`)**

| 모드 | 용도 |
|---|---|
| `PerInstanceColor` · `WorldNormal` · `Checker` | 매핑 검증(라이팅 없음, 저장 안 함) |
| `Radiance` | 구 경로: 월드 삼각형 + 단일 BVH, AO + Direct(`occluderKind` BVH/BruteForce, `bvhQuality`). 알파 미지원 |
| **`RadianceGI`** | 실사용: 2단 BVH 경로추적 Direct + Indirect, CPU/Burst/GPU, 알파·SSAA·로컬 광원·적응·진행형 |

**우클릭 메뉴 전체**

| 메뉴 | 동작 |
|---|---|
| Bake & Apply | 전체 베이크 + 적용 + (라이팅 모드) 저장 |
| Bake Progressive (Preview) · Cancel Progressive Bake | §2.9 |
| Restore Originals | 적용한 uv2 메시·머티리얼·MPB 원복 |
| Save Bake Result (SO + EXR) | 마지막 베이크를 `AtlasBakeAsset` + 페이지 EXR 로 저장 |
| Apply From Bake Asset | `bakeAsset` 으로 적용(베이크 없이). `applyOnEnable` 이면 OnEnable 에 자동 — 플레이/빌드는 이 경로 |
| From DirectionalLight Component | 위 3단계 |
| Collect Scene (C0) · … All Loaded Scenes (C0) | §2.4 |
| Radiance Diff Test (BruteForce vs BVH) | `Radiance` 모드 차폐 백엔드 픽셀 차이(비트 일치 확인) |
| RadianceGI Backend Diff (CPU vs Burst) · (Burst vs GPU) | §2.8 · §2.9 |
| SSAA Self-Tests | §2.11 |
| Alpha Diagnose (알파 효과 측정) | §2.12 |

**결과물**: `outputFolder`(기본 `Assets/CustomLightmapper/BakeOutput`) 에 `<씬>_<이름>_Atlas.asset` + `_page<N>.exr`. 인스펙터 Result: `instanceCount` · `pageCount` · `utilization` · `overflow`(페이지 초과) · `atlas` · `sharedMat` · `progressiveStatus`. `hdrOutput`(기본 on) = RGBAHalf 선형 HDR, 끄면 RGBA32 LDR.

### 2.11 후처리 — Denoise · 시임 스티칭 · Dilation · SSAA

순서: 라이팅(+SSAA) → **Denoise** → **시임 스티칭**(Tier1 정점 · Tier2 모서리) → **Dilation** → 인코딩. 필드는 모두 `AtlasApplyDebug`.

| 단계 | 필드(기본값) | 튜닝 |
|---|---|---|
| SSAA | `ssaaMode`(Off / **Adaptive** 권장 / Full) · `ssaaFactor`(2) · `ssaaEdgeThreshold`(0.10) · `ssaaEdgeNormalAngleDeg`(45) · `ssaaEdgeDilate`(1) · `ssaaDebugMask` | 그림자 외곽 계단 → Adaptive. `ssaaDebugMask` 로 재샘플 텍셀(마젠타) 확인 후 끈다(켠 결과는 못 씀) |
| Denoise | `denoise`(on) · `denoiseIterations`(3) · `denoiseNormalPower`(32) · `denoisePositionSigmaTexels`(2) · `denoiseColorSigma`(0.25) · `denoiseBurst` | 그림자 경계가 뭉개지면 `denoiseColorSigma`↓·`denoiseIterations`↓ |
| 시임 | `seamStitchTier1` · `seamStitchTier2`(on) · `seamStitchIterations`(1) · `seamMaxAngleDeg`(45) | 모서리 밝은 테두리 → `seamMaxAngleDeg`↓ |
| Dilation | `dilate`(on) · `dilateIterations`(4, ≈ `gutterTexels`) · `dilateBurst` · `atlasFilter`(Point/Bilinear) | 차트 경계 검은 선 → `dilate` on, 반복 ≥ gutter |
| GPU 후처리 | `gpuPostProcess` · `postShader` | §2.9 (Denoise 는 CPU 그대로) |

**에디터 메뉴 · 테스트** (RunAll 밖 — 후처리 코드를 바꿨으면 따로 실행)

### 2.12 α — 알파 컷아웃 차폐

잎·펜스처럼 알파 클립 머티리얼의 투명 텍셀을 그림자 레이가 통과한다(any-hit). CPU/Burst/GPU 공통, 텍스처 라이트맵·SH·프로브 볼륨이 같은 코드.

**설정 (`AtlasApplyDebug`, 프로브 볼륨은 같은 이름의 `alpha…` 필드)**

| 필드(기본값) | 설명 |
|---|---|
| `alphaCutoutShadows`(on) | 끄면 쿼드 전체가 불투명(구 거동) |
| `alphaMaskResolution`(256) | 머티리얼당 마스크 해상도 상한 |
| `alphaTransparentPolicy`(Ignore) | 알파 블렌딩 머티리얼(유리·물)은 차폐 제외 |
| `alphaForceCutout` · `alphaForceCutoutNames` | 자동 판별 실패 머티리얼 강제(에셋 참조 / 이름 부분일치 — 예 `Leaf`, `Tree_N_`) |
| `alphaDefaultCutoff`(0.5) | 컷오프 프로퍼티가 없을 때(SpeedTree 0.3333 자동) |

**잎 그림자가 통짜일 때**: ① `mode = RadianceGI` 인지(구 `Radiance` 는 알파 미지원) ② 우클릭 **Alpha Diagnose** — 같은 레이를 알파 on/off 로 쏴서 판정이 뒤집힌 수를 센다. 0 이면 머티리얼 판별·UV·마스크 문제 ③ `alphaForceCutoutNames` 에 셰이더·머티리얼 이름 일부. 베이크 로그 `alpha: …` 에 컷아웃 머티리얼 수·스킵 사유.

### 2.13 SH 인스턴싱 트랙(프롭) — `InstanceSceneBaker`

`DrawMeshInstancedIndirect` 로 그리는 대량 인스턴스에, 인스턴스마다 상/하 2개 SH9 프로브를 굽는다(템플릿 메시 + 인스턴스 행렬). 표시는 `InstancedSH_URP`(태양은 셰이더 실시간, 간접·로컬 광원은 SH).

### 2.14 Track B — 식생 프로브 볼륨 · `ProbeVolumeBaker`

풀·나무처럼 수가 많은 식생에 인스턴스마다 SH 를 굽지 않고, 공간 격자(SH9 프로브)를 한 번 굽고 위치로 샘플한다. 유효성(벽·지면 속 프로브 판정) + dilation, 템플릿 로컬 정점 AO, 알파 잎 차폐 포함.

**사용 순서**

1. 빈 GameObject 에 `ProbeVolumeBaker` 추가 → **볼륨**: 이 Transform 위치 중심의 월드 축 정렬 박스 `volumeSize`(32×8×32) · `probeSpacing`(2,1,2) · `maxProbeCount` 가드.
2. **템플릿(식생)**: `templates` — `mesh` · `albedo` · 행렬(`matrices` / `SetInstances` / `captureSource` + 우클릭 **Capture Matrices From Sources**) · `occluder`(Opaque = 차폐·반사 참여 / Excluded = 표시만) · `twoSided`(잎 카드 — 유효성 뒷면 판정 제외) · `render` · `shading`(InstanceProbes = 상/하 2-프로브 → `InstancedSH_URP` / PerPixelVolume = 픽셀마다 볼륨 샘플 → `InstancedVegetation_URP`) · `material` · `vertexAO` · `alphaMaterials`.
3. **정적 메시(지형·건물)** — `staticSource`:
   - `Roots`(기본, 구 거동): `staticRoots` 하위 MeshFilter 전부.
   - `Collected`: 우클릭 **Collect Scene (C0)** — 텍스처 라이트맵과 같은 C0 분류(Receiver ∪ OccluderOnly)가 `collectedStatics` 로. 템플릿 인스턴스와 겹치는 물체(captureSource 자손 · 메시 + 행렬 일치)는 베이크 때 자동 제외.
   - 공통: `staticDefaultAlbedo`(머티리얼 `_BaseColor`/`_Color` 가 없을 때) · `staticTwoSided`.
4. **광원**: `sun` · `skyTop`/`skyBottom` · `localLights`(§2.7).
5. **베이크**: `backend` · `bounces` · `dirCount`(256) · `seed` · 유효성(`computeValidity` · `validityThreshold` · `validityMaxDistance` · `dilationIterations`) · 알파(`alphaCutout` 외 §2.12) · 정점 AO(`bakeVertexAO` · `vertexAOSettings`) → 우클릭 **Bake** → `<씬>_<이름>_ProbeVolume.asset`(Texture3D 7장 + AO 메시 서브에셋) + EXR. 완료 로그 한 줄에 격자·무효/dilation 수·`lights=`·`alpha=`, 이어서 `scene:`(템플릿·정적 출처·중복 제외 수·BLAS·인스턴스)·`alpha:` 줄.
6. **표시**: 우클릭 **Rebuild Render**(배치만 바뀌면 재베이크 없이 이것만) · **Clear Render**. 표시 필드: `anchorMode`·`surfaceLift`·`liftRelativeToBounds` · `useValidityWeights` · `material`/`vegetationMaterial` · `exposure`·`shStrength`·`translucency` · `normalBiasCells`(누수 완화) · `edgeFadeCells`(볼륨 밖 하늘 폴백) · `bindGlobal`(다른 렌더러도 이 볼륨 사용 — 볼륨 하나만) · `applyVertexAO`·`vertexAOStrength`.
7. **기즈모**(선택 시): 볼륨 박스 · 프로브 구(위쪽 조도 색) · 무효 프로브 빨간 와이어. `drawProbes` · `maxGizmoProbes` · `gizmoProbeSize`.

**테스트** — 묶음 메뉴 **Run Probe Volume Tests (Track B B1-1 ~ B1-6 + C0)**

| 테스트 | 요구 | 확인하는 것 |

**코드를 고친 뒤**
1. 재컴파일 에러·Burst 컴파일 에러·셰이더 경고(X4714 등) 0 확인.

**새 씬을 처음 구울 때**
1. `AtlasApplyDebug` 우클릭 **Collect Scene (C0)** → 리포트의 Excluded 사유 확인(특히 NotReadable).
2. PerInstanceColor 로 매핑 확인 → 미리보기 프리셋으로 RadianceGI → 표준/고품질.
3. 식생은 `ProbeVolumeBaker`(같은 씬에 Collect Scene (C0) → `staticSource = Collected`), 프롭은 `InstanceSceneBaker`.

에디터 확정 체크리스트(v15.12~v15.19 변경분): `03_Progress_And_Validation/에디터검증_체크리스트_v15.12-v15.18.md`.

## 5. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| 메시가 베이크에서 빠짐 / "Read/Write" 경고·오류 | FBX 임포트 **Read/Write Enabled**. C0 리포트의 `NotReadable` 목록 확인 |
| 베이크가 매우 느림 | `radianceBackend` 기본값이 **CPU** → Gpu/Burst. 해상도·spp 를 낮춰 시작, `adaptiveSampling` |
| GPU 를 골랐는데 Burst 로 구움 | 콘솔 폴백 사유: compute 미지원 / `PathTrace.compute` 로드 실패 / BVH 깊이가 GPU 스택 32칸 초과 |
| 차트 경계 검은 선 | `dilate` on, `dilateIterations` ≥ `gutterTexels` |
| 모서리 밝은 테두리(rim) | `seamMaxAngleDeg` ↓ |
| 그레인(자글자글) | `indirectSamples` ↑ · Denoise on · `adaptiveSampling` |
| 그림자 경계 뭉개짐 | `denoiseColorSigma` ↓ · `denoiseIterations` ↓ |
| 잎 경계 점묘 노이즈 | `directSamples` 8~16 + `sunAngularDiameterDeg` 0.53 |
| 그림자 외곽 계단 | `texelsPerWorldUnit` ↑ 또는 SSAA Adaptive |
| 잎 그림자 통짜 | §2.12 (RadianceGI · Alpha Diagnose · `alphaForceCutoutNames`) |
| `overflow = true` | 페이지 초과 → `maxPages` ↑ 또는 `texelsPerWorldUnit` ↓ |
| 곡면이 늘어나 보임 | §2.2 튜닝 |
| 로컬 라이트 추가 후 결과가 달라짐 | 기본 광원 출처가 Scene — 정상. 비교는 `None` |
| 프로브 SH 가 검정 | 대표점이 메시 속 — `anchorMode = SurfaceNormalOffset`, `liftRelativeToBounds` on |
| 프로브 볼륨에 같은 나무가 두 번(너무 어두움) | `staticRoots` 에 식생 부모가 들어감 → 빼거나 `staticSource = Collected`(템플릿 중복 자동 제외) |
| 볼륨 경계·벽 너머 빛 번짐 | `normalBiasCells` ↑, 프로브 간격 ↓, 유효성 on |
| "Collect Scene (C0)" 가 아무것도 안 함 | 프리팹 편집 모드(닫고 다시) 또는 Receiver 0건(경고 로그) |
| 새 테스트 클래스가 IDE 에서 "없음" | Unity 재컴파일 전엔 정상 |
