# P2 출력 분기 설계 — Track A(아틀라스) vs Track B(대표점 SH9)

> 선행: P0/P1 완료(`TemplateInstanceSource` 어댑터 + `TemplateInstanceSourceTests` 등가성).
> 기준: 기획서 v12 §11 「다음 단계」 2번. 이 문서는 **b(P2 분기) 진행용 설계**.
> 원칙: **코어(TwoLevelBVH/InstancedRadianceScene/RadianceCore) 무수정**, 기존 CPU를 ground truth로 ε-교차검증.

---

## 1. 현재 위치 (P0/P1 산출물)

`TemplateInstanceSource.BuildScene(input)` → `MatrixInstanceScene`:

| 필드 | 내용 | P2에서 쓰임 |
|---|---|---|
| `uniqueMeshes` `Tri[][]` | 템플릿당 로컬 삼각형 | 두 트랙 공통(BLAS) |
| `meshAlbedo` `Vector3[]` | per-template Linear 알베도 | 두 트랙 공통 |
| `instances` `Instance[]` | `{MeshIndex, L2W}` | 두 트랙 공통(차폐/GI) |
| `bvh` / `scene` | `TwoLevelBVH` / `InstancedRadianceScene`(모드 A) | 두 트랙 공통 |
| **`instancePoints` `Vector3[]`** | 대표점 = M·bounds.center | **Track B(SH) 입력** |
| `instanceTemplate` `int[]` | 인스턴스→템플릿 | 편의 |

→ **공통 씬(차폐·GI)은 이미 완성.** P2는 "인스턴스별 **출력 표현**"만 정한다.

## 2. 분기 개요

```
BuildResult ┬→ Track A: per-instance 텍스처 아틀라스   ← 소규모 N (uv2/ST 존재)
            └→ Track B: 대표점 → SH9 프로브            ← 대량 N (DrawMeshInstancedIndirect)
```

| 축 | Track A (아틀라스) | Track B (SH9) |
|---|---|---|
| 대상 | 정적 프롭 소량 | 식생·대량 인스턴스 |
| 인스턴스당 출력 | 아틀라스 영역(ST) + 텍셀 | SH9(9×float3) |
| 확장성 | ✗ N개 아틀라스 영역 → 대량 불가 | ✅ 인스턴스당 27 float |
| 신규 작업량 | 소(기존 아틀라스 경로 MeshFilter만 탈피) | 중(SH 투영 베이커 신규) |
| 원 동기(인스턴싱) 적합 | 낮음 | **높음** |

**권장: Track B 우선.** 원 요구(Mesh+Matrix 대량 인스턴싱)가 Track B이고, 어댑터가 이미 `instancePoints`를 그 용도로 산출한다. Track A는 소규모 검증용으로 후순위.

---

## 3. Track A — per-instance 텍스처 아틀라스 (소규모 N)

### 3.1 데이터 흐름 (MeshFilter 경로에서 MeshFilter만 제거)

```
per-template: ParameterizationPipeline.Run(mesh)  → uv2(공유)
per-instance: LightmapAllocator.Allocate(InstanceLM{WorldArea(mesh,M)}) → ST
              TexelMapper.Map(uv2mesh, res, M)     → LumelMap(worldPos/normal/valid)
              texel별 EvaluateRadiance(scene,…)     → 아틀라스 Blit
              후처리(stitch→dilate)                  → RGBAHalf
```

### 3.2 재사용 vs 신규

| 구성 | 처리 |
|---|---|
| `WorldArea(Mesh, Matrix4x4)` / `Allocate` / `Run(Mesh)` / `Map(Mesh,res,Matrix4x4)` | **무수정 재사용**(이미 Mesh+Matrix 시그니처) |
| 텍셀 베이크·Blit·후처리 | **무수정 재사용** |
| 알베도 | 어댑터 `meshAlbedo` 사용 |
| **적용/표시** | **신규·범위 밖** — MeshFilter 스왑 대신 **ST를 인스턴스 버퍼로**(DrawMeshInstancedIndirect 셰이더) |

### 3.3 한계 · 리스크
- **확장성**: 인스턴스마다 아틀라스 영역 → N 커지면 페이지 폭증. **소규모 전용**.
- uv2는 템플릿 공유지만 ST·텍셀은 per-instance → 대량이면 Track B로 가야 함.
- 표시 경로(인스턴스 버퍼 ST)는 런타임 셰이더 과제(코어 무관).

---

## 4. Track B — 대표점 SH9 프로브 (대량 N) ★권장

### 4.1 개념
각 인스턴스 대표점 `p = instancePoints[i]` 에서 **방향 조도(directional irradiance)** 를 전구(全球) 샘플로 캡처해 **SH9(L2, 9계수 × 3채널)** 로 투영. 프로브는 단일 노멀이 없으므로 표면점이 아닌 **볼륨 대표점**을 쓴다(어댑터가 이미 산출).

몬테카를로 투영:
```
c_lm = (4π / N) · Σ_k  L(p, ω_k) · Y_lm(ω_k)      // ω_k ~ uniform sphere (pdf = 1/4π)
L(p, ω_k) = 레이 p→ω_k 최근접 히트의 출사 라디언스(-ω_k 방향), 미스면 sky(ω_k)
```

### 4.2 재사용 vs 신규

| 구성 | 처리 |
|---|---|
| `TwoLevelBVH.IntersectInstanced`/`ClosestHit`(위치·역전치 노멀·알베도) | **무수정 재사용** |
| `ISky`, `Rng`, 균등구 샘플 | 재사용(+균등구 샘플러 필요 시 소량 추가) |
| 히트점 출사 라디언스 | `EvaluateRadiance(scene, hit, n, …)` **재사용**(또는 Direct+1bounce 근사) |
| **`RadianceSH.Evaluate(scene, p, sun, sky, q, seed)` → SH9** | **신규**(투영 누적) |
| Burst 미러 `BurstSH`(G3와 동형 IJobParallelFor) | 신규(정확성 확정 후) |
| 출력: per-instance SH9 → 인스턴스 `StructuredBuffer` | 신규(런타임 표시) |

### 4.3 결정 필요 항목 (⚠ 사용자 확인)
1. **SH 차수** — L1(4계수, 저장·성능 유리) vs **L2(9계수, 기획서 계약 "SH9")**. 기획서 §3은 SH9(L2) 결정.
2. **L(p,ω) 정의** — (a) 최근접 히트에서 `EvaluateRadiance`(Direct+Indirect 완전) vs (b) 1-바운스 근사(성능). 정확도/속도 트레이드오프.
3. **저장·표시** — SH9를 인스턴스 버퍼에 어떻게 싣고 셰이더에서 어떻게 평가할지(런타임, 코어 무관).

### 4.4 검증 전략 (RadianceIndirectTests 계승)
- **등방 하늘·빈 씬** → L0(DC)만 유의, L1/L2 ≈ 0(방향성 없음).
- **방향 하늘/태양** → 해당 방향 L1 정렬(부호·축 일치).
- **닫힌 흑박스** → 전 계수 0(에너지보존).
- **대칭 씬** → 대칭 계수쌍 상쇄.
- (선택) 순수 방향광 → Unity `SphericalHarmonicsL2.AddDirectionalLight` 해석해와 대조.
- 결정성: per-instance 시드 `seed + i*2654435761u`(텍셀 규약과 동일).

### 4.5 리스크
- **Track B 분산(노이즈)** — SH 저계수는 적분이라 텍셀 GI보다 spp에 관대하나, 고주파 환경은 링잉. spp·클램프.
- 대표점이 지오메트리 내부/관통 → 자기차폐 편향. bias·대표점 보정(다중 대표점 평균 옵션).
- 대량 N → 프로브 수 = 인스턴스 수. Burst 병렬(G1 AO와 동형)로 감당.
