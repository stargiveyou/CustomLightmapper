# 커스텀 라이트매퍼 — 디버그 / 테스트 도구 레퍼런스

> 코드의 모든 Debugger·Test·Tool 클래스 사용법. (갱신: 2026-06-18, 코드 대조 — BVHTests 정정, Indirect/모드B/RadianceGI 반영)
> 네임스페이스: `HuskyLibs.CustomLightmapper.Bake`(에디터 `.EditorTools`).

## 0. 도구 3종류 & 호출 방식

| 종류 | 위치 | 호출 |
|---|---|---|
| **MonoBehaviour 디버거** | 씬 GameObject에 컴포넌트로 부착 | 인스펙터 **우클릭 → ContextMenu** |
| **static 테스트 클래스** | 코드/디버거에서 호출 | `Debug.Log(X.RunAll())` |
| **Editor 메뉴/윈도우** | `Test/Editor/` | 상단 메뉴바 |

## 1. MonoBehaviour 디버거 (씬에 부착 → 우클릭)

### A1~A3 — UV 파라미터화

| 컴포넌트 | ContextMenu | 용도 |
|---|---|---|
| **ChartSegmentationDebugger** | Run Segmentation / Run Segmentation - Welded / Clear Result | 차트 분할 결과를 기즈모/오버레이로 시각화. Welded는 용접본 기준 |
| **HalfEdgeConversion** | Rebuild HalfEdge | `WeldedHalfEdge` 시각화 — 하프에지 화살표, 경계(boundary) 에지 강조. `bIsDrawHalfEdge` 등 토글 |
| **ParameterizationTestDebugger** | Run Parameterization Check / Clear Result | A1~A3 파이프라인(분할→평탄화) 구동·검증 |
| **UVAssemblerTestDebugger** | Run UV Assemble / Clear Result | uv2 메시 조립 + SeamTable 검증 |

### A4 — 텍셀 · per-instance ST · 아틀라스

| 컴포넌트 | ContextMenu | 용도 |
|---|---|---|
| **TexelMapperDebug** | Run Texel Map / Save Preview PNG / Clear Result | `LumelMap`(worldPos/normal/valid)을 프리뷰 텍스처·기즈모로. PreviewMode(WorldNormal/WorldPos/ValidMask), packing 토글 |
| **LightmapAllocatorDebug** | Run Self Tests / Run Full Tests / Run Mesh Test | per-instance ST 할당 검증(기본 2케이스 / 확장 11케이스 / 실제 메시 면적→할당) |
| **AtlasApplyDebug** | **Bake & Apply** / **Restore Originals** | A4 ST + TexelMapper 통합 검증 → 아틀라스 굽고 오브젝트에 적용. ↓상세 |

**AtlasApplyDebug 모드(`mode`)**
- `PerInstanceColor` / `WorldNormal` / `Checker` — 매핑 검증(라이팅 없음)
- `Radiance` — 텍셀마다 `EvaluateRadiance`(AO+Direct+그림자) 베이크 = **실제 라이트맵 머티리얼**
  - `occluderKind`: **BruteForce**(정답·느림) / **BVH**(가속) — 둘로 구워 머티리얼 시각 대조 = BVH 정확성 검증
  - `bvhQuality`: Median / SAH
  - 주의: 브루트포스라 비쌈 → `atlasResolution` 128~256, `aoSamples` 16~32로 시작
  - **Radiance Diff Test (BruteForce vs BVH)** ContextMenu — 같은 텍셀에서 두 백엔드 radiance 픽셀 차이 측정
- `RadianceGI` — **2단 인스턴싱 경로추적**(`InstancedRadianceScene`+`TwoLevelBVH`) Indirect 베이크. 유니크 메시(로컬)+per-mesh 알베도+인스턴스로 씬 구성, `EvaluateRadiance(scene, …)`(Direct+Indirect) 평가
  - 매우 느림 → `atlasResolution` 128~256, `indirectSamples` 16~32, `maxBounces` 1~2 권장

### C2 — 라이팅 코어 (BVH 없이 동작)

| 컴포넌트 | ContextMenu | 용도 |
|---|---|---|
| **LightmapEvaluateDebugger** | **Evaluate** / Run All Tests (C1+C2) / Run Self Tests / Run Indirect Tests / Run Mode-B Albedo Tests / Run BVH Cross·Mesh·Scene Tests / Clear | C2 라이팅 씬 시각화 + 전체 테스트 진입점 묶음. ↓상세 |
| **InstancedSceneTester** | **Run Instanced Scene Test** | 2단(TwoLevelBVH+InstancedRadianceScene) ≡ brute(BruteForce+RadianceScene) 교차검증. ClosestHit 위치·노멀·알베도 + Indirect 대조. 같은 메시 다중 인스턴싱(BLAS 공유) 검증 |
| **BVHGizmoDebugger** (`Occluders/Test/`) | **Build BVH** / Clear / **Create Ray Handles** | 단일레벨 BVH 씬뷰 시각화. ① 노드 AABB 와이어박스: targets(비우면 자식 MeshFilter) 월드 Tri 스냅샷 빌드, minDepth/maxDepth 층 필터, leafOnly, 깊이별 색, quality(Median/SAH) 비교, 통계(nodes/tris/depth/sahCost) 라벨. ② 레이 순회: RayOrigin/RayTarget 핸들 이동 → Intersect 복제 순회를 라이브 실행, 방문 노드 강조·컬링 노드 회색(옵션)·히트 지점/삼각형 표시, `visited/culled/triTests/T` 통계 = 컬링 동작 눈 확인. 트랜스폼 이동 시 재빌드 필요 |

**LightmapEvaluateDebugger**
- **Evaluate** — receiver 메시 정점마다 AO/Direct/Radiance 평가 → 기즈모 구체 색(선택 시 표시). `channel`로 전환, `surfaceBias`로 acne 제어
- **Run All Tests (C1+C2)** → 토대(`LightmapEvaluateTests`) + BVH(`BVHTests`) + Indirect(`RadianceIndirectTests`) + 모드B(`InstancedSceneModeBTests`) 일괄
- **Run Self Tests** → `LightmapEvaluateTests.RunAll()` (C2 코어 해석적 테스트)
- **Run Indirect Tests** → `RadianceIndirectTests.RunAll()` (경로추적: 빈씬→π·L, 흑박스→0, 에너지보존, RR 무편향)
- **Run Mode-B Albedo Tests** → `InstancedSceneModeBTests.RunAll()` (2단 인스턴싱 submesh 알베도 정확성 + 경계 안전)
- **Run BVH Cross Tests** → `BVHTests.RunAll()` (합성 씬 단일레벨+2단 BVH≡brute)
- **Run BVH Mesh Test** → `BVHTests.RunMeshTest(receiver mesh)` (실제 메시 BVH≡brute)
- **Run BVH Scene Test (multi-mesh)** → `BVHTests.RunSceneTest(occluders)` (다중 MeshFilter: 병합 단일레벨 + 2단 인스턴스 동시 대조)
- *Random Translate* — 빈 스텁(미구현)

## 2. static 테스트 클래스 (코드에서 호출)

`Debug.Log(...)` 로 콘솔에 `n/n PASS` 리포트를 찍습니다.

| 클래스.메서드 | 검증 대상 |
|---|---|
| `LightmapEvaluateTests.RunAll()` | **C2 코어**(해석적 known-answer): RayTri(히트/미스/컬링/평행/양면) · BruteForceOccluder(최근접/차폐) · CosineHemisphere(E[cosθ]≈2/3) · AO(0/1/결정성) · Direct(정면/백페이스/그림자) · Radiance 합성 |
| `BVHTests.RunAll()` | **BVH≡BruteForce** 차등검증(합성): 두평면·grid·box·random·단일·빈 씬 + **2단 TLAS/BLAS**, Median/SAH 둘 다, 무작위 레이로 Intersect/Occluded 대조 (구 `BVHCrossTests` 흡수) |
| `BVHTests.RunMeshTest(mesh, l2w, rays=2000)` | 위와 동일하나 **실제 Mesh** 를 월드 Tri[]로 변환해 단일레벨 검증 |
| `BVHTests.RunSceneTest(filters, rays=3000)` | 다중 MeshFilter 씬을 ① 병합 단일레벨 BVH ② 유니크 메시 BLAS+인스턴스 2단 으로 동시에 brute 대조 |
| `RadianceIndirectTests.RunAll()` | **C2 Indirect**(경로추적+RR): 빈씬→π·L · 하늘0→0 · 흑박스(α0)→0 · 회색박스+무광원→0(에너지보존) · RR≈no-RR(무편향) |
| `InstancedSceneModeBTests.RunAll()` | **2단 인스턴싱 모드B**(per-instance submesh 알베도): ground truth 대조 정확성 + null/짧음/음수 매핑 경계 안전(예외X·Fallback) |
| `LightmapAllocatorTests.RunAll()` | per-instance ST 할당 확장 테스트(엣지케이스 포함) |
| `LightmapPostProcessCompare.RunAll()` | **Dilation 백엔드**: Burst(`LightmapPostProcessBurstJob`) ≡ 직렬(`LightmapPostProcess`) 픽셀 일치 + 성능(best-of-N) |
| `LightmapDenoiseCompare.RunAll()` | **Denoise 백엔드+품질**: Burst(`LightmapDenoiseBurstJob`) ≡ 직렬(`LightmapDenoise`) 픽셀 일치 · 노이즈 RMS ≤0.5× · 그림자 엣지 대비 보존 · 원거리 차트 격리 + 성능 |
| `LightmapAllocator.RunSelfTests()` | 할당 기본 2케이스(1/2/0.5 변 비율, 200큐브 멀티페이지) |
| `BruteForceOccluder.RunSelfTests()` | `LightmapEvaluateTests.RunAll()` 로 위임(동일 진입점) |

> 해석: `miss=0` / `n/n PASS` = 통과. BVH 교차검증의 `miss>0`은 BVH 순회/컬링 버그 신호.

> MonoBehaviour 인스턴싱 테스트: `InstancedSceneTester` (씬 오브젝트에 부착 → 우클릭 **Run Instanced Scene Test**) 도 참조(§1).

## 4. 권장 검증 워크플로

1. **코어부터 격리 검증** — `LightmapEvaluateDebugger` → **Run All Tests (C1+C2)** 한 번으로 토대·BVH·Indirect·모드B 일괄(`n/n PASS`, `miss=0`).
2. **단계별 시각 확인** — A1~A3 디버거(차트/조립) → A4(TexelMapperDebug, AtlasApplyDebug의 WorldNormal/Checker).
3. **라이팅 머티리얼** — AtlasApplyDebug `mode=Radiance`, `occluderKind=BruteForce`로 정답 베이크 → `BVH`로 바꿔 **머티리얼 시각 대조**(동일해야 BVH 정확).
4. **이상 시** — 항상 static 테스트로 어느 계층이 깨졌는지 먼저 격리. BVH 의심이면 Run BVH Mesh Test로 실제 지오메트리 대조.

## 5. 공통 주의
- 기즈모형 디버거(LightmapEvaluate/TexelMapper 등)는 **오브젝트 선택 시에만** 표시되고, 필드 변경 후 **재실행** 필요(자동 갱신 아님).
- 임포트 메시(FBX)는 **Read/Write Enabled** 필요(아니면 가드 메시지).
- 새로 만든 테스트 클래스는 Unity **재컴파일** 전까지 IDE에서 `없음` 에러로 보일 수 있음(정상).
