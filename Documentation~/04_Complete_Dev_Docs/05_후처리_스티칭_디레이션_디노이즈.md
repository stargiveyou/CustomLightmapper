## 0. 실제 파이프라인 순서 (`AtlasApplyDebug.BakeAndApply`)

```
BlitRegion (텍셀 → 아틀라스 페이지, valid 마스크 + 가이드 노멀/위치 기록)
   ↓
3.3  Denoise           ← À-trous joint bilateral (valid 텍셀만)
   ↓
3.4  Seam Stitch T1    ← 정점 그룹 평균
     Seam Stitch T2    ← 모서리 segment Jacobi 평균
   ↓
3.5  Push-Pull Dilation ← 거터/배경을 인접 valid 평균으로 확장
   ↓
4    Texture2DArray.SetPixels → Apply
```

**순서 근거**(코드 주석에 명시):

| 단계 | 왜 이 위치인가 |
|---|---|
| Denoise **먼저** | 경계 텍셀 값을 먼저 안정화해야 스티칭·확장이 매끈하다. 노이즈가 남은 채 평균하면 그레인이 시임을 따라 번진다 |
| Stitch **다음** | 경계 값을 일치시킨 뒤 그 값을 거터로 확장해야 한다 |
| Dilate **마지막** | 거터 전파는 최종 값 기준이어야 의미가 있다 |

세 단계 모두 **valid 텍셀만 읽고**, Denoise/Stitch는 valid 텍셀에만 쓴다(배경·거터 불변).
Dilate만 valid 마스크를 확장한다.

## 1. 디노이즈 — À-trous Joint Bilateral (최신 추가)

### 1.1 문제

몬테카를로 베이크(AO·경로추적)는 텍셀마다 독립 난수로 적분하므로 **고주파 그레인**이 남는다.
색만 블러하면 하드 엣지·차트 경계·그림자 경계가 뭉개진다.

### 1.2 해법 — 베이크가 이미 가진 정보를 가이드로

`LumelMap`의 **텍셀별 월드 노멀·월드 위치**를 가이드로 쓰는 에지 보존 필터.

```csharp
// Runtime/Denoise/LightmapDenoise.cs:9
public struct DenoiseSettings
{
    public int   Iterations;      // à-trous 패스 수(step = 1,2,4,…). 3이면 유효 반경 ≈ 17텍셀
    public float NormalPower;     // pow(max(0,dot), p). 클수록 각진 면 분리 강함(하드 엣지 보존)
    public float PositionSigma;   // 월드 위치 가우시안 σ(월드 단위, step 1 기준 — 커널 내부에서 step 배율)
    public float ColorSigma;      // 색 range σ(Linear RGB L2). 그림자 경계 등 라이팅 엣지 보존

    public static DenoiseSettings Default => new DenoiseSettings
    {
        Iterations     = 3,
        NormalPower    = 32f,
        PositionSigma  = 0.125f,    // texelsPerWorldUnit=16 기준 2텍셀
        ColorSigma     = 0.25f,
    };
}
```

탭 가중치 = **B3 커널 × 노멀 × 위치 × 색**:

```csharp
// Runtime/Denoise/LightmapDenoise.cs:47
static readonly float[] K = { 1f/16f, 4f/16f, 6f/16f, 4f/16f, 1f/16f };   // B3 스플라인 {1,4,6,4,1}/16
```

```csharp
// Runtime/Denoise/LightmapDenoise.cs:93
float wt = K[dx + 2] * K[dy + 2];
if (nidx != idx)
{
    float ndot = Mathf.Max(0f, Vector3.Dot(cN, normal[nidx]));
    wt *= Mathf.Pow(ndot, s.NormalPower);                         // ① 노멀

    Vector3 dp = worldPos[nidx] - cP;
    wt *= Mathf.Exp(-Vector3.Dot(dp, dp) * invTwoSigP2);          // ② 위치

    Color nc = src[nidx];
    float dr = nc.r - cC.r, dg = nc.g - cC.g, db = nc.b - cC.b;
    wt *= Mathf.Exp(-(dr*dr + dg*dg + db*db) * invTwoSigC2);      // ③ 색 (RGB L2)
}
```

| 가이드 | 막는 것 |
|---|---|
| ① **노멀** `pow(dot, p)` | 다른 방향 면(큐브 모서리 등) 혼합 — `seamMaxAngleDeg` 게이팅과 같은 원리 |
| ② **위치** 가우시안 | 아틀라스에서 인접해도 월드에서 먼 텍셀(다른 차트) → **차트 간 bleed 차단** |
| ③ **색** range | 노이즈 진폭보다 큰 라이팅 엣지(직사 그림자 경계) 보존 |

**③이 휘도 스칼라가 아니라 RGB L2 거리인 이유**:
휘도는 단일 채널 엣지를 과소평가한다. 예를 들어 순수 R 채널 0.7 계단은 휘도로 환산하면 0.15에 불과해
필터가 "노이즈"로 오판하고 번진다. 색 있는 GI(코넬박스형 색번짐)에서 특히 중요.

### 1.3 à-trous — σ에 step을 곱하는 이유

```csharp
// Runtime/Denoise/LightmapDenoise.cs:63
int step = 1 << it;
// σ는 step 배율 — 연속 표면에서 탭 거리(∝step)와 σ가 같이 늘어 감쇠가 step 불변.
float sigP = Mathf.Max(1e-6f, s.PositionSigma * step);
```

탭 간격이 `step`배로 벌어지므로 σ를 고정하면 큰 step에서 모든 탭이 기각된다.
σ에 step을 곱하면 **연속 표면에서는 감쇠가 step 불변**이고, **불연속(차트 점프)만 기각**된다.

더블버퍼 스왑 + 홀수 패스 보정:

```csharp

...
```

## 2. 시임 스티칭 Tier1 — 정점

### 2.1 문제

같은 원본 정점에서 갈라진 uv2 정점들(`SeamTable.Groups`)은 아틀라스의 **서로 다른 텍셀**에 떨어져
독립적으로 구워진다 → 차트 경계에서 조도 불연속.

### 2.2 해법 — 그룹 텍셀 평균

```csharp
// Runtime/LightmapStitch/Lightmapseamstitch.cs:81
public static void Stitch(Color[] pixels, bool[] valid, List<int[]> texelGroups)
{
    foreach (var g in texelGroups)
    {
        if (g == null || g.Length < 2) continue;

        Color sum = Color.clear; int validCount = 0;
        for (int i = 0; i < g.Length; i++)
        {
            int idx = g[i];
            if (idx < 0 || idx >= pixels.Length) continue;
            if (valid[idx]) { sum += pixels[idx]; validCount++; }
        }
        if (validCount < 2) continue;          // 평균 낼 valid 가 2개 미만이면 무의미

        Color average = sum / validCount;
        for (int i = 0; i < g.Length; i++)
        {
            int idx = g[i];
            if (idx < 0 || idx >= pixels.Length || !valid[idx]) continue;
            pixels[idx] = average; valid[idx] = true;
        }
    }
}
```

**순수 함수** — 아틀라스 텍셀 인덱스 그룹만 받는다(헤드리스 검증 가능).
uv2 → 텍셀 매핑은 호출측(`AtlasApplyDebug`)이 인스턴스 ST로 수행한다:

```csharp
// Runtime/LightmapStitch/Lightmapseamstitch.cs:58
public static int Uv2ToTexelIndex(Vector2 uv, int ox, int oy, int sidePx, int res)
{
    int tx = Mathf.Clamp(Mathf.FloorToInt(uv.x * sidePx), 0, sidePx - 1);
    int ty = Mathf.Clamp(Mathf.FloorToInt(uv.y * sidePx), 0, sidePx - 1);
    int ax = ox + tx, ay = oy + ty;
    if (ax < 0 || ax >= res || ay < 0 || ay >= res) return -1;
    return ay * res + ax;
}
```

블릿과 **동일한 (ox, oy, sidePx, res) 매핑**을 쓰므로 텍셀이 정확히 정렬된다.

## 3. 시임 스티칭 Tier2 — 모서리 (Route A)

Tier1은 정점만 맞춘다. 모서리 **중간 텍셀**은 여전히 불연속이다.

### 3.1 시임 모서리 쌍 유도 — `SeamEdgeBuilder.Build`

**원리**: 3D에서 잘린 한 모서리는 UV에서 두 차트의 **경계 모서리**로 나타나고,
두 끝점이 각각 같은 그룹(같은 원본 정점)에 속한다.
→ "경계 모서리(삼각형 1개만 접함)" 중 **양 끝점이 서로 다른 시임 그룹**인 것을
무순 그룹쌍 `{gA, gB}`로 묶으면 한 시임이 된다.

```csharp
// Runtime/LightmapStitch/SeamEdgeBuilder.cs:51
// 2) 무향 모서리 → 접하는 삼각형 수 (경계 모서리 = 1)
var edgeCount = new Dictionary<long, int>();
for (int t = 0; t + 2 < triangles.Length; t += 3)
{ Bump(edgeCount, a, b); Bump(edgeCount, b, c); Bump(edgeCount, c, a); }

// 3) 경계 모서리 중 양 끝점이 모두 시임 그룹(서로 다른 그룹) → {gA,gB} 로 묶음
foreach (var kv in edgeCount)
{
    if (kv.Value != 1) continue;                       // 경계 모서리만
    DecodeEdge(kv.Key, out int va, out int vb);
    int ga = groupOf[va], gb = groupOf[vb];
    if (ga < 0 || gb < 0 || ga == gb) continue;

    int lo = Mathf.Min(ga, gb), hi = Mathf.Max(ga, gb);
    long pKey = ((long)lo << 32) | (uint)hi;

    // 끝점 정규화: VA ∈ lo그룹, VB ∈ hi그룹 → 미러/뒤집힌 UV에서도 t 방향 일치
    int vA = (ga == lo) ? va : vb;
    int vB = (ga == lo) ? vb : va;
    ...
}
// 4) 양쪽(>=2 모서리)이 있는 시임만 채택
```

**끝점 정규화가 핵심**: 두 차트의 UV가 미러되거나 뒤집혀 있어도
`(lo그룹 끝점, hi그룹 끝점)` 순서로 통일하면 파라미터 `t` 방향이 서로 일치한다.

무향 모서리 키는 64bit 패킹(`(lo << 32) | hi`)으로 `(a,b)`와 `(b,a)`가 같은 키가 된다.

### 3.3 공유 t Jacobi 평균 — `StitchEdges`

```csharp
// Runtime/LightmapStitch/Lightmapseamstitch.cs:127
public static void StitchEdges(Color[] slice, bool[] valid, int res,
                               List<Seg[]> segmentGroups, int iterations = 1)
{
    var sum = new Dictionary<int, Color>(); var count = new Dictionary<int, int>();
    var perT = new List<int>(8);

    for (int iter = 0; iter < Mathf.Max(1, iterations); iter++)
    {
        sum.Clear(); count.Clear();

        foreach (var segs in segmentGroups)
        {
            if (segs == null || segs.Length < 2) continue;

            // 가장 긴 segment 기준 샘플 수 → 짧은 쪽도 빠짐없이 같은 t로 매핑
            float maxLen = 0;
            for (int s = 0; s < segs.Length; s++)
                maxLen = Mathf.Max(maxLen, Vector2.Distance(segs[s].A, segs[s].B));
            int N = Mathf.Max(1, Mathf.CeilToInt(maxLen));

            for (int i = 0; i <= N; i++)
            {
                perT.Clear();
                float t = i / (float)N;
                Color r = Color.clear; int vc = 0;

                // 공유 t 에서 각 segment 의 텍셀을 모아 valid 합산
                for (int s = 0; s < segs.Length; s++)
                {
                    Vector2 p = Vector2.Lerp(segs[s].A, segs[s].B, t);
                    int tx = Mathf.Clamp(Mathf.FloorToInt(p.x), 0, res - 1);
                    int ty = Mathf.Clamp(Mathf.FloorToInt(p.y), 0, res - 1);
                    int idx = ty * res + tx;
                    if (idx < 0 || idx >= slice.Length || !valid[idx]) continue;
                    if (perT.Contains(idx)) continue;      // 같은 텍셀 중복 합산 방지
                    perT.Add(idx); r += slice[idx]; vc++;
                }
                if (vc < 2) continue;

                Color avg = r / vc;                        // 이 t 의 대표값 P
                for (int k = 0; k < perT.Count; k++) { /* sum[idx] += avg; count[idx]++ */ }
            }
        }

        // Jacobi: 이번 iteration 의 누적 평균을 일괄 기록(다음 iteration 이 갱신값을 읽음)
        foreach (var kv in sum) slice[kv.Key] = kv.Value / count[kv.Key];
    }
}
```

**Jacobi 누적을 쓰는 이유**: 한 텍셀이 여러 시임에 동시에 걸리거나(다중 시임 교차),
두 segment 길이가 달라 매핑이 1:1이 아닌 경우가 있다.
즉시 갱신(Gauss-Seidel)하면 **처리 순서에 따라 결과가 달라진다**.
한 iteration의 누적 평균을 일괄 기록하면 **순서 무관하게 안정적으로 수렴**한다.
끝점도 이 N-way 수렴에 참여하므로 Tier1(정점)은 보조 역할이 된다.

## 5. Push-Pull Dilation

### 5.1 문제

베이크는 valid 텍셀만 칠하고 거터/무효 텍셀은 배경색으로 남는다.
bilinear 샘플이 배경을 끌어와 **검은 시임**이 보인다.

### 5.2 직렬판 — `LightmapPostProcess.Dilate`

```csharp
// Runtime/Diliation/LightmapPostProcess.cs:20
public static void Dilate(Color[] px, bool[] valid, int w, int h, int iterations)
{
    var cur = (bool[])valid.Clone();
    for (int it = 0; it < iterations; it++)
    {
        var next = (bool[])cur.Clone();
        bool changed = false;

        for (int y = 0; y < h; y++)
        for (int x = 0; x < w; x++)
        {
            int idx = y * h + x;
            if (cur[idx]) continue;               // valid 텍셀은 절대 덮어쓰지 않음

            float r=0,g=0,b=0,a=0; int cnt = 0;
            for (int dy = -1; dy <= 1; dy++)      // 3×3, 중앙 제외 = 8방
            for (int dx = -1; dx <= 1; dx++)
            {
                if (dx == 0 && dy == 0) continue;
                ...
                if (!cur[nidx]) continue;         // '패스 시작 시점 valid' 만 소스 → 정확한 링 확장
                ... 누적 ...
            }
            if (cnt > 0) { px[idx] = 평균; next[idx] = true; changed = true; }
        }
        cur = next;
        if (!changed) break;                      // 직렬판 전용: 조기 종료
    }
    System.Array.Copy(cur, valid, valid.Length);  // 채운 텍셀은 이제 valid → 입력 마스크에 되쓰기
}
```

**핵심 규칙 2가지**:
1. valid 텍셀은 **절대** 덮어쓰지 않는다 → 베이크 결과 보존.
2. 소스는 **패스 시작 시점의 valid**만 → 한 패스가 정확히 링 1개만 확장한다
   (즉시 갱신하면 한 패스에서 여러 링이 번져 결과가 순서 의존이 된다).

> ⚠ 인덱싱 `int idx = y * h + x;` — 정방형(`w == h`) 아틀라스에서만 정확하다.
> Burst 판은 `y * W + x`로 올바르다. 현재 아틀라스는 항상 정방형이라 실사용에 문제는 없지만
> 비정방형 입력 시 직렬판만 어긋난다.

### 5.3 Burst 판 — `LightmapPostProcessBurstJob`

더블버퍼 핑퐁 + 핸들 체이닝:

```csharp
// Runtime/Diliation/LightmapPostProcessBurstJob.cs:81
for (int it = 0; it < iterations; it++)
{
    var job = new DiliateJob { W = w, H = h, SrcPx = srcPx, SrcValid = srcValid,
                               DstPx = dstPx, DstValid = dstValid };
    lastHandle = job.ScheduleParallel(px.Length, 256, lastHandle);   // 패스 간 핸들 체이닝

    (srcPx, dstPx)       = (dstPx, srcPx);      // 더블버퍼 스왑
    (srcValid, dstValid) = (dstValid, srcValid);
    resultInOriginal = !resultInOriginal;       // 실제 스왑 횟수 추적
}
lastHandle.Complete();

if (!resultInOriginal) { scratchPx.CopyTo(px); scratchValid.CopyTo(valid); }
```

각 인덱스는 **자기 위치(`DstPx[index]`)에만 쓰므로 병렬 안전**하다.
Src에서만 읽고 Dst에만 쓰므로 한 패스 내 읽기/쓰기 충돌이 없다.
직렬판의 `changed` 조기 종료는 Burst판에 없다(스왑 횟수 추적으로 대체).

진입점 2종:
- `Dilate(Color[], bool[], w, h, it)` — 관리형(기존 시그니처 유지, 내부 변환)
- `DilateBurst(NativeArray<float4>, NativeArray<bool>, w, h, it)` — Job 파이프라인 직결

검증: [`LightmapPostProcessCompare`](../../Tests/LightmapPostProcessCompare.cs) — Burst ≡ 직렬 + 성능.
