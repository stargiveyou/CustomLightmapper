## 2. 아키텍처 결정 — "출력 표현 2개, 파이프라인 1개"

가장 중요한 1차 결정. **트레이서·가속구조를 트랙별로 분기하지 않는다**(리스크 1순위).

```
                    ┌──────────────── 공유 코어 ────────────────┐
  SceneCollector →  │  BVH / TwoLevelBVH  →  RadianceCore       │
      (미구현)       │  (C1)                  EvaluateRadiance    │
                    │                        + ISky / 광원        │
                    └───────────────┬───────────────────────────┘
                                    │  단일 진입점
                    ┌───────────────┴───────────────┐
              Track A (건물·프롭)             Track B (식생·대량)
              텍스처 라이트맵                 Light Probe / SH9
              UV 파이프라인 전체              대표점 프로브(주) + 정점(보조)
```

| 구성 | 결정 | 구현 |
|---|---|---|
| 공유 코어 | 단일 `EvaluateRadiance(point, normal)` 진입점 | [`RadianceCore.cs:192`](../../Runtime/LightmapEvaluate/RadianceCore.cs#L192) |
| 차폐 추상화 | `IOccluder` 유지 (BruteForce로 교차검증) | [`Occluder.cs:12`](../../Runtime/LightmapEvaluate/Occluders/Occluder.cs#L12) |
| Track A | 텍스처 라이트맵 + UV2/ST | `UVAssembly/` `TexelMapper/` `LightmapAllocator/` |
| Track B | SH9 프로브 (per-instance) | `SH/` `Burst/BurstSHBaker.cs` |

## 3. 공유 계약 (변경 금지 항목)

| 계약 | 결정 | 실제 구현 위치 |
|---|---|---|
| 색 공간 | **Linear 전 구간** | `SceneRadianceBuilder` sRGB→Linear 변환, 알베도 폴백 0.5 |
| SH 차수 | **SH9 = L2, 9 × float3** | [`SH9.cs:19`](../../Runtime/SH/SH9.cs#L19) |
| 광원 강도 단위 | 통일·선형 | `DirectionalLight{Direction, Color, Intensity}` |
| 라이트맵 인코딩 | **RGBAHalf**(최종 출력) | `AtlasApplyDebug.hdrOutput` 토글 |
| 라이트맵 저장량 | **조도(irradiance)** — 점 알베도는 런타임 적용 | `RadianceCore` 주석 명시, 바운스 표면 알베도만 베이크 |
| 시드 규약 | `seed + index * 2654435761u` | CPU/Burst/GPU 3백엔드 공통 |
| 페이지 해상도 | 1024×1024 (기본) | `AllocationSettings.Default` |
| 텍셀 밀도 | 10~64 texels/unit | `TexelsPerWorldUnit = 64f`(코드 기본), 인스펙터 16f |

> **인코딩 주의**: 디버그 도구 `AtlasApplyDebug`는 표시용으로 RGBA32 + 감마(`ToColor`)를 쓴다.
> RGBAHalf는 `hdrOutput` ON일 때의 최종 출력 경로다. 충돌이 아니라 **단계가 다르다**.
> RGBAHalf(선형 저장)에서는 스티칭·디레이션 평균이 **선형에서 정확**해진다(v11에서 감마 근사 caveat 해소).

## 5. 인스턴싱 × 라이트맵 — 하이브리드 결정 (기획서 §7)

정적 대량(`DrawMeshInstancedIndirect`) 씬을 **메시 크기로 갈라 출력 표현을 바꾼다**.

| 대상 | 출력 | 이유 |
|---|---|---|
| **대형 메시**(건물 5~10종) | 텍스처 라이트맵(`AtlasApplyDebug`) | 벽면별 그림자/바운스 표현 필요. 종류가 적어 ST·아틀라스 부담 없음 |
| **소형 메시**(프롭 ~수만) | **per-instance SH9** `StructuredBuffer` | 인스턴스당 27 float. 50k × 112B ≈ 5.6MB |

핵심 규칙 3가지:

1. **차폐 씬(2단 BVH)에는 크기 무관 전부 포함** → 서로 그림자/바운스를 주고받음.
2. **직사광은 SH 밖**(셰이더 실시간) → L2 링잉·그림자 뭉개짐 방지. SH엔 간접+환경만.
3. **코어 무수정** — SH 경로는 어댑터(`TemplateInstanceSource`) + `BurstSHBaker`로 분리.
   `AtlasApplyDebug`는 텍스처 전용으로 유지하고 씬 구성·광원·시드 규약·백엔드 패턴만 재사용.

2단 BVH 메모리는 **∝ 메시 종류 수**(월드 전개 없음) → 대량 인스턴스에 적합.

## 6. P2 출력 분기 설계 — Track A vs Track B (별도 설계 문서)

`01_Planning_And_Design/커스텀_라이트매퍼_P2_출력분기_설계.md` 요지:

| 축 | Track A (아틀라스) | Track B (SH9) |
|---|---|---|
| 대상 | 정적 프롭 소량 | 식생·대량 인스턴스 |
| 인스턴스당 출력 | 아틀라스 영역(ST) + 텍셀 | SH9 (9×float3) |
| 확장성 | ✗ N개 아틀라스 영역 → 대량 불가 | ✅ 인스턴스당 27 float |
| 신규 작업량 | 소 | 중(SH 투영 베이커 신규) |
| 원 동기 적합도 | 낮음 | **높음** |

→ **Track B 우선 채택**. 어댑터가 이미 `instancePoints`를 그 용도로 산출하고 있었다.

SH 몬테카를로 투영 정의(설계 문서 §4.1 → 실제 `SH9.Accumulate`로 구현):

```
c_lm = (4π / N) · Σ_k  L(p, ω_k) · Y_lm(ω_k)      // ω_k ~ uniform sphere (pdf = 1/4π)
L(p, ω_k) = 레이 p→ω_k 최근접 히트의 출사 라디언스, 미스면 sky(ω_k)
```

설계 시 미결이던 §4.3 결정 3건은 다음과 같이 확정되었다:

| 결정 항목 | 확정 결과 |
|---|---|
| SH 차수 L1 vs L2 | **L2(9계수)** — 기획 §3 계약 유지 |
| `L(p,ω)` 정의 | **(b) 1-바운스 근사** + 하늘 앰비언트 (`BurstSHBaker.Incoming`) |
| 저장·표시 | `SHPacked` 7×float4 → `StructuredBuffer<float4>`(stride 16) → `EvaluateSH9.hlsl` |

## 8. 리스크 관리 (기획서 §10) — 현재 상태

|---|---|---|
