# 09 — 검증 · 테스트 매트릭스

> 검증 철학: **CPU가 ground truth, Burst/GPU는 미러 후 ε-교차검증.**
> 기존 정답(BruteForce · RadianceCore)을 절대 버리지 않고 매 단계 대조한다.

---

## 0. 검증 계층

```
BruteForceOccluder  ← 절대 기준(가속구조 없음)
      │  ≡
   BVH / TwoLevelBVH ← C1
      │  ≡
   RadianceCore      ← C2 (해석해 항등식으로도 검증: π·L, 흑박스 0, RR 무편향)
      │  ≡ (ε)
   Burst (G0~G3)     ← 프리미티브 재사용 → 비트동일
      │  ≡ (ε)
   GPU  (G4~G6·SH-G) ← HLSL 미러 → 통계/near-bit-identical
      │
   실 씬 육안 검증   ← 라이트 OFF에서도 조명 유지 = 순수 베이크 확정
```

## 1. 한 버튼 회귀 — `LightmapEvaluateDebugger.RunAllTests`

`[ContextMenu("Run All Tests (C1+C2)")]` 하나로 **14종**이 순차 실행된다.

```csharp
// Samples/LightmapEvaluateDebugger.cs:59
public void RunAllTests()
{
    sb.AppendLine(LightmapEvaluateTests.RunAll());        // C2 토대(RayTri/BruteForce/AO/Direct)
    sb.AppendLine(BVHTests.RunAll());                     // C1 가속구조(BruteForce 정답 대조)
    sb.AppendLine(RadianceIndirectTests.RunAll());        // C2 Indirect(경로추적)
    sb.AppendLine(InstancedSceneModeBTests.RunAll());     // 2단 인스턴싱 모드B(submesh 알베도)
    sb.AppendLine(BurstSceneTests.RunAll());              // G0 Burst POD ≡ 관리형 TwoLevelBVH
    sb.AppendLine(BurstRadianceCompareTests.RunAll());    // G2/G3 Burst Direct/Indirect ≡ RadianceCore
    sb.AppendLine(TemplateInstanceSourceTests.RunAll());  // P1 Mesh+Matrix 어댑터 ≡ MeshFilter 경로
    sb.AppendLine(SH9BakeTextureTest.RunAll());           // SH-1 SH9 프로젝션/조도 항등식
    sb.AppendLine(BurstSHBakerTests.RunAll());            // SH-2 per-instance SH9
    sb.AppendLine(SHPackedTests.RunAll());                // SH-3 SHPacked 7×float4 왕복
    sb.AppendLine(SHEvalProbeGpuTests.RunAll());          // SH-5 셰이더 디코드 ≡ CPU (렌더 컨텍스트 필요)
    sb.AppendLine(GpuBvhCompareTests.RunAll());           // G4 GPU 순회 ≡ Burst (compute 필요)
    sb.AppendLine(GpuRadianceCompareTests.RunAll());      // G5 GPU 경로추적 ≡ Burst (compute 필요)
    sb.AppendLine(GpuSHBakeCompareTests.RunAll());        // SH-G GPU CSSHBake ≡ BurstSHBaker
}
```

## 7. 실측 게이트 체크리스트 (재컴파일 후 확인 순서)

`03_Progress_And_Validation/실측게이트_체크리스트.md` 요약 + 현재 상태 반영.

### 사전 (스테일 방지 — 가장 중요)

- [ ] Burst 컴파일 강제 리프레시 (Jobs ▸ Burst ▸ Enable Compilation). 의심 시 `Library/BurstCache` 삭제
- [ ] 에디터 재컴파일 → 컴파일 에러 **0**
- [ ] asmdef 참조 정상(Runtime/Editor/Tests/Samples 4분할)
- [ ] Burst 실측 속도는 **Play 모드/빌드**에서 재측정(에디터 Mono 오버헤드 배제)

### 비자명성 관찰점 ★

| 관찰점 | 실패 시 의미 |
|---|---|
| G0 **hits > 0** | `IntersectBlas` `hT` 초기화 회귀 → closest-hit 전부 실패 |
| G2/G3 **nonZero > 0** | 씬/알베도/시드 연결 오류 |
| 폴백 경고 없음 | GPU 백엔드가 실제로 안 돌고 Burst로 떨어짐 |

### 실패 시 우선 의심 지점

| 증상 | 우선 의심 |
|---|---|
| G0 hits=0, closest-hit 전부 실패 | `IntersectBlas` `hT` 초기화(= tmax) 회귀 |
| `IJobParallelFor IndexOutOfRange` | `BurstScene` NativeArray `[ReadOnly]` 누락 |
| 종료 시 누수 경고 | `meshAlbedo`·`GpuIoBuffers`·`GraphicsBuffer` Dispose 누락 |
| CPU↔Burst mean 큼 | 시드 규약(`seed + li*2654435761u`) 불일치 / 알베도 연결 / 씬 dedup |
| Burst 결과 전부 0 | Sky/알베도/텍셀 valid 연결 |
| 화면 마젠타 | URP 셰이더 × BIRP 파이프라인 |
| Burst가 CPU보다 느림 | 에디터 Mono(Play/빌드 재측정) / batch 크기 |
| SH 인스턴스 색 오독 | `_InstanceSH` stride(16) vs 버퍼 stride 불일치 |
| SH 프로브 검정 | 대표점이 솔리드 내부 → `AnchorMode.SurfaceNormalOffset` |
| GPU X4714 경고 | 순회 스택 크기(`BVH_STACK`) — fxc `/T cs_5_0`로 확인 |
