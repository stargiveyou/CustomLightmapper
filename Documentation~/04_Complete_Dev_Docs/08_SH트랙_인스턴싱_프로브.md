# 08 — SH 트랙: 인스턴싱 per-instance SH9 프로브

> 상태: **✅ SH-1 ~ SH-5 + SH-G 완료 · 검증** (URP 확정, BIRP 보류)
> 실측: GPU 디코드 ≡ CPU (ε 2e-3) · SH-G GPU 베이크 ≡ Burst (mean **1.0e-8** → near-bit-identical)

## 1. 왜 SH 트랙인가 (기획 §7 하이브리드)

| 대상 | 출력 | 비용 |
|---|---|---|
| 대형 메시(건물 5~10종) | 텍스처 라이트맵 | 종류가 적어 아틀라스 부담 없음 |
| **소형 메시(프롭 ~수만)** | **per-instance SH9** | 50k × 112B ≈ **5.6MB** |

규칙 3가지:
1. 차폐 씬(2단 BVH)에는 **크기 무관 전부 포함** → 서로 그림자/바운스를 주고받는다.
2. **직사광은 SH 밖**(셰이더 실시간) → L2 링잉·그림자 뭉개짐 방지. SH엔 간접+환경만.
3. **코어 무수정** — 어댑터 + 별도 베이커로 분리.

### 2.2 프로브 대표점 배치 — `AnchorMode` ★

**문제**: 대표점이 솔리드 메시 내부(AABB 중심)에 있으면 자기차폐로 **SH = 0(검정)** 이 된다.

```csharp
// Runtime/TemplateInstanceSource.cs:42
public enum AnchorMode
{
    Auto,                 // surfaceLift>0 → LocalTopLift, 아니면 Center (하위호환 기본)
    Center,               // 로컬 AABB 중심. 솔리드 내부 → 갇힘. 하위호환/디버그용
    LocalTopLift,         // 로컬 +Y 윗면 중앙 + surfaceLift(로컬 단위, M 스케일 비례). 얇은/볼록 프롭용
    WorldUpLift,          // 로컬 윗면 중앙을 변환 후 월드 +Y 로 surfaceLift(월드 단위) 이동
    SurfaceNormalOffset,  // 실제 최상단 삼각형 표면점 + 외향 법선·여백 ★ 권장(임의 메시·회전에 견고)
}
```

```csharp
// Runtime/TemplateInstanceSource.cs:111
public static void ComputeLocalAnchor(AnchorMode mode, Bounds b, Tri[] tris, float surfaceLift,
                                      bool top, out Vector3 localAnchor, out float worldLift)
{
    worldLift = 0f;
    if (mode == AnchorMode.Auto) mode = surfaceLift > 0f ? AnchorMode.LocalTopLift : AnchorMode.Center;
    float sign  = top ? 1f : -1f;
    float faceY = top ? b.max.y : b.min.y;

    switch (mode)
    {
        case AnchorMode.Center:        localAnchor = b.center; return;
        case AnchorMode.LocalTopLift:  localAnchor = new Vector3(b.center.x, faceY + sign * surfaceLift, b.center.z); return;
        case AnchorMode.WorldUpLift:   localAnchor = new Vector3(b.center.x, faceY, b.center.z);
                                       worldLift   = sign * surfaceLift; return;   // 여백은 월드에서

        case AnchorMode.SurfaceNormalOffset:
        {
            // 최상단/최하단(centroid.y 극값) 삼각형의 표면점 + 외향 법선으로 ε 만큼 밀어 솔리드 밖 표면 근접.
            // ε 은 ClosestHit tMin(1e-4) 보다 크게(자기히트 방지).
            float eps = Mathf.Max(surfaceLift, 1e-3f);
            Vector3 c = b.center, n = sign * Vector3.up;
            float bestY = top ? float.NegativeInfinity : float.PositiveInfinity;
            for (int i = 0; i < tris.Length; i++)
            {
                Vector3 ct = (tris[i].V0 + tris[i].V1 + tris[i].V2) * (1f / 3f);
                if (top ? ct.y <= bestY : ct.y >= bestY) continue;
                Vector3 nrm = Vector3.Cross(tris[i].V1 - tris[i].V0, tris[i].V2 - tris[i].V0);
                float mag = nrm.magnitude;
                if (mag < 1e-12f) continue;                                   // 퇴화 삼각형 skip
                nrm /= mag;
                if (Vector3.Dot(nrm, ct - b.center) < 0f) nrm = -nrm;         // 외향 보정
                bestY = ct.y; c = ct; n = nrm;
            }
            localAnchor = c + n * eps;
            return;
        }
    }
}
```

> **`SurfaceNormalOffset`이 권장인 이유**: 스칼라 리프트는 "AABB 윗면 = 표면" 가정에 의존한다.
> 데모 박스에는 성립하지만 **구·토러스·오목 메시나 회전 인스턴스**에서는 대표점이 허공/오배치되어
> SH 대표성을 잃는다. 실 표면점 + 외향 법선은 **형상·회전 무관하게 솔리드 밖 표면 근접**을 보장한다.

`top` 파라미터가 있는 이유: **2-프로브(상/하)** 를 대칭으로 산출하기 위함(§6.3).

const float k0  = 0.2820948f;   // 1/(2√π)

const float k2a = 1.0925484f;   // √(15/4π)   (xy, yz, xz)
const float k2b = 0.3153916f;   // √(5/16π)   (3z²-1)

const float A0 = Mathf.PI;      // π
const float A1 = 2.0943952f;    // 2π/3
const float A2 = 0.7853982f;    // π/4

**이 세 세트가 4곳에서 1:1로 미러된다**: `SH9.cs`(베이크·기즈모) / `EvaluateSH9.hlsl`(런타임) /
`PathTrace.compute ShBasis`(GPU 베이크) / `SHEvalProbe.shader`(검증).
하나라도 어긋나면 런타임과 기즈모 색이 달라진다.

### 3.2 프로젝션 · 평가

```csharp
// Runtime/SH/SH9.cs:89
/// coeff += L·Y(d)·weight   (weight = 4π/N, 구 균등 샘플 pdf=1/4π 의 역수)
public void Accumulate(Vector3 d, Vector3 L, float weighten)
{
    Basis(d, out float y0, ..., out float y8);
    c0 += L * y0 * weighten;
    ...
    c8 += L * y8 * weighten;
}

// Runtime/SH/SH9.cs:109
/// 노멀 n 방향 Lambert 조도 재구성 E(n) (albedo 미포함). 음수는 0 클램프.
public Vector3 Evaluate(Vector3 n)
{
    Basis(n, out float y0, ..., out float y8);
    Vector3 e = c0 * (A0 * y0)
              + (c1*(A1*y1) + c2*(A1*y2) + c3*(A1*y3)) * W1
              + (c4*(A2*y4) + c5*(A2*y5) + c6*(A2*y6) + c7*(A2*y7) + c8*(A2*y8)) * W2;
    return new Vector3(Mathf.Max(0f, e.x), Mathf.Max(0f, e.y), Mathf.Max(0f, e.z));
}
```

## 4. SH-2 — `BurstSHBaker` (per-instance SH9 베이크)

```csharp
// Runtime/LightmapEvaluate/Burst/BurstSHBaker.cs:27
[BurstCompile]
public struct SHJob : IJobParallelFor      // 인스턴스 병렬
{
    public BurstScene Scene;  public BurstSky Sky;  public DirectionalLight Sun;
    [ReadOnly] public NativeArray<Vector3> Points;   // 인스턴스 대표점
    [ReadOnly] public NativeArray<Vector3> Dirs;     // 구면 균등 방향셋(공유)
    public float Weight;                             // 4π/N
    [WriteOnly] public NativeArray<SH9> Out;

    public void Execute(int index)
    {
        Vector3 p = Points[index];
        var sh = new SH9();
        for (int s = 0; s < Dirs.Length; s++)
        {
            Vector3 d = Dirs[s];
            sh.Accumulate(d, Incoming(p, d), Weight);
        }
        Out[index] = sh;
    }
```

### 4.1 입사 조도 정의 (1-bounce · 결정적)

```csharp
// Runtime/LightmapEvaluate/Burst/BurstSHBaker.cs:50
Vector3 Incoming(Vector3 p, Vector3 d)
{
    if (BurstTwoLevelBVH.ClosestHit(Scene, p, d, 1e-4f, float.MaxValue, out var hp, out var hn, out var albedo))
    {
        // 이웃 표면이 받는 조도 = 태양(그림자 포함) + 하늘 앰비언트.
        Vector3 irr = DirectAt(hp, hn) + AmbientAt(hn);
        return new Vector3(albedo.x*irr.x, albedo.y*irr.y, albedo.z*irr.z);
    }
    return Sky.Radiance(d);   // 미스: 하늘
}

// 그늘/뒷면 이웃도 하늘빛을 받아 반사한다(1-bounce 앰비언트 근사).
private Vector3 AmbientAt(Vector3 hn) => Sky.Radiance(hn);
```

> **`AmbientAt`이 왜 필요한가** (v13.3 아티팩트 ①):
> 앰비언트가 없으면 그늘진 이웃 방향이 **정확히 0(검정)** 이 되어 하부 반구가
> "색 or 완전검정" 이진 패치워크로 무너지고, **L2 재구성 링잉이 증폭**되어 단색(빨강) 얼룩이 된다.
> 하늘 복사휘도를 앰비언트 조도로 쓰면 하부 반구에 **양수 DC 바닥**이 생겨 완전검정이 제거된다.

**RNG를 쓰지 않는다** — 고정 피보나치 방향셋이라 완전 결정적이다.

### 4.2 피보나치 구면 방향셋

```csharp
// Runtime/LightmapEvaluate/Burst/BurstSHBaker.cs:107
public static NativeArray<Vector3> FibonacchiSphere(int n, Allocator alloc)
{
    var pts = new NativeArray<Vector3>(n, alloc);
    float golden = Mathf.PI * (3.0f - Mathf.Sqrt(5f));     // 황금각 ≈ 137.5°
    for (int i = 0; i < n; i++)
    {
        float y = 1f - (i + 0.5f) / n * 2.0f;
        float r = Mathf.Sqrt(Mathf.Max(0, 1f - y * y));
        float theta = golden * i;
        pts[i] = new Vector3(r * Mathf.Cos(theta), y, r * Mathf.Sin(theta));
    }
    return pts;
}
```

정다면체 방식과 달리 **임의 개수 N**을 균등 배치할 수 있다.

> ⚠ **주의(코드 주석)**: 대표점이 솔리드 메시 내부면 자기차폐로 어두워진다.
> 점 배치는 **호출측 책임**(`AnchorMode`). 얇은 프롭은 근사 OK, 큰 메시는 텍스처 경로로.

## 5. SH-G — GPU SH 베이크 (`CSSHBake`)

`BurstSHBaker.SHJob`의 **정확 미러**. 스레드 = 프로브.

```hlsl
// Shaders/Resources/PathTrace.compute:624
[numthreads(64, 1, 1)]
void CSSHBake(uint3 id : SV_DispatchThreadID)
{
    uint i = id.x;
    if ((int)i >= _Count) return;
    float3 p = _Points[i];

    float3 c0 = 0, ..., c8 = 0;

    [loop] for (int s = 0; s < _DirCount; s++)
    {
        float3 d = _Dirs[s];
        float3 L = ShIncoming(p, d);

        float y0, ..., y8;
        ShBasis(d, y0, y1, y2, y3, y4, y5, y6, y7, y8);

        c0 += L * y0 * _ShWeight;
        ...
        c8 += L * y8 * _ShWeight;
    }
    GpuSH9 sh; sh.c0 = c0; ...; _ShOut[i] = sh;
}
```

```hlsl
// Shaders/Resources/PathTrace.compute:607  — BurstSHBaker.Incoming 미러
float3 ShIncoming(float3 p, float3 d)
{
    float3 hp, hn, alb;
    float3 result = SkyRadiance(d);                          // 미스 기본값(하늘)
    if (ClosestHitNA(p, d, 1e-4, hp, hn, alb))               // ⚠ tmin=1e-4 (BurstSHBaker 규약)
    {
        float3 irr = DirectNEE(hp, hn) + SkyRadiance(hn);    // 태양(그림자 포함) + 하늘 앰비언트
        result = alb * irr;
    }
    return result;                                           // 단일 반환(fxc X4000 false-positive 회피)
}
```

### 5.1 near-bit-identical의 비결

```csharp
// Runtime/LightmapEvaluate/Gpu/GpuSHBaker.cs:9
/// Burst 와 동일 방향셋을 쓰기 위해 피보나치 방향은 CPU(BurstSHBaker.FibonacchiSphere)에서 계산해
/// _Dirs 로 업로드한다(GPU 재계산 금지 → sqrt/sin/cos 하드웨어 발산 제거). 방향·기저(다항식)·순회가
/// 일치하므로 결과는 near-bit-identical(전이함수 없음).
```

- **방향은 CPU에서 계산해 업로드** → 초월함수 발산 제거
- **`ShBasis`는 순수 다항식**(cos/sin 없음)
- **순회는 G4 검증분**

세 조건이 겹쳐 **초월함수가 경로에서 완전히 사라진다**.

**실측**: 48프로브 × 256방향 — mean **1.0e-8**, max **3.0e-7**, over(1e-4) = **0/432**.

### 5.2 회귀 안전성

`ClosestHitNA`에 `tmin` 매개변수를 추가하면서 기존 경로는 **0.0으로 명시 전달**하여 G5 거동을 보존했다.
검증: G5 4/4 PASS (Direct 8.3e-10 · AO 0 · Indirect 2.5e-9 — **이전과 동일 수치**) +
`CSRadiance ≡ CSDirect + CSIndirect`(mean 0, 비트동일).

### 5.3 실 배선 (v14.10)

`SHRenderDemo`에 `ShBakeBackend { Burst, Gpu }` 토글(기본 Burst).
compute 미지원 / 셰이더 로드 실패 / 커널 미발견 시 **Burst 자동 폴백**.
`try/finally`로 topPts/botPts·gpuScene 해제(예외 시 무누수).

시각 확인: `shBakeBackend = Gpu` → 수백 인스턴스(2템플릿 녹/살구 알베도) SH 조명 정상 렌더,
2프로브 면별 수직음영, 아티팩트 없음.

### 6.2 🔴 stride 정합 (v13.2 실제 버그)

```csharp
// Runtime/SH/SHInstanceBuffer.cs:77
// 셰이더는 _InstanceSH 를 StructuredBuffer<float4>(stride 16)로 보고 프로브당 7개를
// 연속 인덱스로 읽는다(EvaluateSH9.hlsl). 따라서 버퍼도 반드시 float4 × (total·7),
// stride 16 으로 만들어야 stride 정합(112 로 만들면 SRV stride 불일치 → 오독/바인딩 거부).
var flat = new Vector4[total * SHPacked.Float4Count];
for (int i = 0; i < total; i++)
{
    var p = SHPacked.Pack(SH[i]);
    int b = i * SHPacked.Float4Count;
    flat[b+0]=p.p0; flat[b+1]=p.p1; ... flat[b+6]=p.p6;
}
var buf = new GraphicsBuffer(GraphicsBuffer.Target.Structured,
                             total * SHPacked.Float4Count, sizeof(float) * 4);
buf.SetData(flat);
return new SHInstancedBuffer { Buffer = buf, Count = n };   // Count = 인스턴스 수(렌더러 정합 검사용)
```

원래는 `GraphicsBuffer(Structured, n, 112)`로 만들었으나, 셰이더가 `StructuredBuffer<float4>`(stride 16)로
`instanceID*7+k` 인덱싱하므로 **SRV stride 불일치**(112 vs 16)가 발생해 인스턴스 간 계수를 오독했다.
바이트 총량은 같지만(n × 112B) **뷰 stride가 달라야 한다**.

> `SHPackedTests`는 CPU Pack/Unpack만 검증하므로 이 GPU 경로 버그를 잡지 못했다 — **런타임 육안 검증에서만** 드러났다.
> 이것이 나중에 `SHEvalProbeGpuTests`(실 StructuredBuffer 왕복 검증)를 만든 동기다.

### 7.2 2-프로브 임의 축 보간 (v13.3 → v14.2)

```hlsl
// Shaders/EvaluateSH9.hlsl:96
// 2-프로브(상단=probe0, 하단=probe1) 블렌드 (임의 축 upW).
//   레이아웃: base = instanceID*14, top = base..base+6, bottom = base+7..base+13
//   블렌드: w = saturate(dot(n, upW)*0.5+0.5)  (n∥upW→top, n∥-upW→bottom, 직교는 선형)
//   upW = 인스턴스 로컬 up 의 월드 방향 → 임의 3축 회전에서도 상/하 프로브 배치와 정합
float3 EvaluateInstanceSH2Axis(StructuredBuffer<float4> buf, uint instanceID, float3 n, float3 upW)
{
    uint bt = instanceID * 14u;      // top    probe base
    uint bb = bt + 7u;               // bottom probe base
    float3 eTop = EvaluateSH9(UnpackProbe(buf, bt), n);
    float3 eBot = EvaluateSH9(UnpackProbe(buf, bb), n);
    float w = saturate(dot(n, upW) * 0.5 + 0.5);
    return lerp(eBot, eTop, w);
}

// 월드 +Y 고정 축 위임(Y회전만 있는 씬 하위호환). 거동은 기존과 비트동일(dot(n,(0,1,0)) == n.y).
float3 EvaluateInstanceSH2(StructuredBuffer<float4> buf, uint instanceID, float3 n)
{ return EvaluateInstanceSH2Axis(buf, instanceID, n, float3(0.0, 1.0, 0.0)); }
```

> **왜 2-프로브인가** (v13.3 아티팩트 ④): 인스턴스당 프로브 1개(윗면 위)를 전 노멀에 외삽하면
> **면별 음영이 소실**되어 평평해 보인다. 상단(`LocalTopLift`) + 하단(로컬 AABB `min.y - surfaceLift`)
> 2세트를 굽고 노멀 축으로 lerp하면 **하늘↔바닥 수직 그라디언트가 면별로 복원**된다
> (박스 top 밝고 bottom 어두움, 구 상하 음영). BVH 핫패스는 무변경 — 대표점만 2배.
> 측면(±X/±Z) 구분은 각 프로브의 L1 x/z 항이 담당한다.

**노멀 역전치를 HLSL에서 직접 계산**(`inverse()` 내장이 없음):

```hlsl
// Shaders/InstancedSH_URP.shader:53
// U 의 행이 a,b,c 이면 U⁻¹ 의 '열'은 (b×c, c×a, a×b)/det → (U⁻¹)ᵀ 의 '행'이 그 값들.
float3x3 NormalMatrix(float4x4 m)
{
    float3x3 u = (float3x3)m;
    float3 a = u[0], b = u[1], c = u[2];
    float3 r0 = cross(b, c), r1 = cross(c, a), r2 = cross(a, b);
    float det = dot(a, r0);
    float invDet = (abs(det) > 1e-8) ? 1.0 / det : 0.0;
    return float3x3(r0 * invDet, r1 * invDet, r2 * invDet);
}
```

// Shaders/InstancedSH_URP.shader:93
half4 frag(Varyings i, bool isFront : SV_IsFrontFace) : SV_Target
{
    float3 worldSpaceNormal = normalize(i.worldN);
    float3 n = isFront ? worldSpaceNormal : -worldSpaceNormal;   // 백페이스 플립(양면 렌더 정합)
    float3 albedo = _Color.rgb;

    // (1) 간접 + 환경: SH9 조도 × albedo
    float3 upAxis = normalize(i.upW);
    float3 shIrradiance = EvaluateInstanceSH2Axis(_InstanceSH, i.iid, n, upAxis) * _SHStrength;
    float3 indirect = albedo * shIrradiance;

    // (2) 직사광: URP 메인 라이트 실시간(SH 밖) + 그림자
    float4 shadowCoord = TransformWorldToShadowCoord(i.worldP);
    Light  mainLight   = GetMainLight(shadowCoord);
    float  ndl   = saturate(dot(n, mainLight.direction));
    float  atten = mainLight.shadowAttenuation * mainLight.distanceAttenuation;
    float3 direct = albedo * mainLight.color * (ndl * atten);

    return half4((indirect + direct) * _Exposure, 1.0);
}
